# 0. OPERATING CONTRACT

## 0.1 Allowed terminal states

Every D-series task must terminate as exactly one of:

- **IMPLEMENTED** — missing mechanism, contract, evidence pipeline, or mapping is landed through canonical owners and required focused gates are green.
- **DECIDED-DEFERRED** — product/architecture/release/balance policy requires a signed decision; exact deferred scope is explicit.
- **RETIRED** — obsolete heuristic, duplicate authority, stale release hook, fallback path, or dead asset mapping is removed with reference proof.
- **VERIFIED-RESOLVED** — current `HEAD` already satisfies the plan contract; duplicate work is skipped and evidence recorded.
- **ROUTED-REPAIR** — investigation reveals a genuine defect outside bounded scope; a repair package with characterization evidence is registered.

No task may close as “mostly done,” “future”, “manual QA only”, “probably reproducible”, or “TBD”.

## 0.2 Mandatory non-negotiable rules

1. **Godot remains authoritative; Unity stays retired.**
2. **Core remains engine-free.**
3. **JSON/data authority remains canonical.**
4. **One authority per concern.** No second relationship ledger, balance simulation truth source, version authority, asset registry, or release manifest source.
5. **Deterministic replay.** No wall-clock timing or unordered iteration may affect Core simulation.
6. **Claims before edits.**
7. **Exactly 20 procedural substeps per task.**
8. **Exactly four mini-substeps per mini-task.**
9. **Focused verification first.**
10. **Build warning baseline may not worsen.**
11. **No hidden balance policy.** Draft values such as +15%, 0.5x–2.5x, 30-day golden, under-15s CI, or fixed difficulty preset names are examples until verified by Plan 44/46/48/50 or current signed policy.
12. **No silent telemetry.** Any player/session metric collection must be strictly local, opt-in where required, privacy-bounded, and clearly separated from developer simulation artifacts.
13. **No fake release guarantees.** A patch release is save-safe only if the current compatibility contract proves it; do not encode SemVer rules that conflict with actual save/data compatibility policy.
14. **No duplicate asset truth.** D4 must reconcile existing `asset_registry`, `AssetRegistry`, data catalogs, and generator pipeline before introducing any `AssetCatalog`.
15. **Fallback must be explicit.** Asset fallback resolution is a typed non-success path.
16. **Snapshot testing must be robust.** Do not require zero-pixel drift across platforms unless the existing renderer/test policy guarantees pixel-identical output.
17. **Generated artifacts are regenerated from source.**
18. **Every task writes an implementation log and updates census/ledger truth.**
19. **Release scripts must not tag/publish from a dirty or unverified tree unless current policy explicitly permits.**
20. **Wave 13 or maintenance planning must consume final merged Wave 12 evidence, not draft numbering.**

## 0.3 Universal pre-edit evidence bundle
