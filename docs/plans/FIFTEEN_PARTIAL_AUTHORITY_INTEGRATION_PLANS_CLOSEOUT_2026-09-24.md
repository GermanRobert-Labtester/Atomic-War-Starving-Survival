## Finished integration architecture for this planning wave

```text
current authored JSON or canonical campaign facts
    → one engine-free Core owner or pure evaluator
    → one claimed Godot host command/day adapter
    → existing save-section owner where state changes
    → read-only panel, atlas, briefing, memorial, or radio projection
```

The architecture is **specified**, with three mandatory owner decisions still open for implementation: caravan session consolidation; Standing Record versus ExpansionHub memory/encounter persistence; and the separation or sharing of ideology affinity between the social coordinator and Plan 148 event host. These are explicitly gated rather than silently solved in prose. Debt payment additionally needs the canonical funds/goods transaction authority; eulogy generation needs a proven provider and life-record source. A foreman must claim exact production paths in `WORKTREE_OWNERSHIP.md` before promotion. The current active batch in `INTEGRATION_PLANS.md` remains the execution authority.

## Dependency order for promotion

1. **Resolve collisions and stale classifications.** Map constructor identity, Main field, day caller, panel binding, and save section for caravans, the Standing Record family, and ideology. Correct a historical `PARTIAL`/`NON-INT` label if the player route is already present.
2. **Establish one bounded command per subject.** Prefer a current catalog row and existing Core API. For pure Utility AI scoring, no new private save is needed. For stateful systems, capture and restore through the present owner.
3. **Bind cross-owner effects through receipts.** Funds and goods, radiation dose, quest access, faction standing, patrol selection, and memorial creation stay with their existing owners. A refusal produces no success effect. An accepted event is applied once and is replay safe.
4. **Expose a truthful read route.** The UI shows current eligibility, confidence, refusal, history, and cost from the live owner. It maintains keyboard/controller close and focus behavior and refreshes from saved state without reissuing commands.
5. **Promote only reviewed content.** The master expansion authority's clusters C2, C5, C6, C7, C8, C9, C11, C12, C13, and C17 supplied narrative directions and continuity constraints. The generated case registers are deliberately **non-canon**. Their prose must be reduced to specific rows with a trigger, information source, loader, consumer, and localization route before any JSON authoring. The master document's scale-honesty clause forbids counting bulk draft text as verified gameplay content.
