# Plan 14: Underpass Settlements, Hidden Routes, and Wasteland Infrastructure

**Status:** Starter expansion wave plus Continuation Wave 2; documentation-only, premise-gated, and not an implementation claim. **Wave target:** Plans 13–16 synchronized multi-edit, with distinct mechanics, story content, locations, shelter lore, character arcs, factions, and late-game material.

**Domain:** subsurface routes, linked settlements, shelter infrastructure, expedition logistics, and hidden travel.

**Current-owner boundary:** Candidate work must route through CartographySystem, expedition and route owners, vehicle and colony owners, ShelterExpansionSystem, WeatherSystem, CommunicationsSystem, and the existing map/POI authority. No second faction ledger, relationship store, map graph, shelter counter, ending resolver, legacy store, or parallel save section may be created.

## Scope and non-duplication contract

This plan treats a tunnel chalk arrow beneath a bridge, a rusted gate key, a cistern map folded in oilcloth, and a shelter bell hung in a culvert as authored anchors for a new playable layer. They are not assumed to exist in the shipped catalog. The current source audit must verify IDs, consumers, host construction, save registration, and live claims before any row becomes implementation-ready. The proposed signals — route confidence, gate condition, water reach, shelter occupancy, weather blockage, supply fatigue, and return depth — are read models or content prerequisites until an owner is named.

The proposed cast and political vocabulary are deliberately provisional: Cinder Arch Wardens, Morrow Culvert Cooperative, Blue Sump Keepers, Hearthline Carriers, and the Nine-Latch Union. The late-game proposal is a proposed late-game Cinderworks Compact that links underpass settlements into a regional infrastructure authority only after existing colony, route, and faction owners are proven sufficient. Existing diplomacy, standing, relationship, map, roster, archive, campaign, ending, and legacy behavior remains authoritative. Where an existing system already expresses a requested outcome, this plan supplies content, projection, UX, or a bridge rather than a replacement.

## Nine synchronized expansion passes

### Pass 1: Chalk Arrow Census

#### Field 1 — Canon, premise, and evidence boundary

This pass turns the proposal into a reviewable slice with a named owner and a visible player outcome. Begin with a route census rather than inventing a second map. CartographySystem already owns discovery and survey progress, while expedition and vehicle systems own travel outcomes. This plan proposes a hidden-route layer that stores provenance, confidence, gate state, and narrative tags only if the current map authority exposes a compatible read and write seam. In this pass, the gate is the concrete review token: it must be visible in data, UI, journal, or a focused assertion before the slice can advance. The design review should name the owning file or public seam, the source fact that proves the premise, and the smallest observable result a player would see.
