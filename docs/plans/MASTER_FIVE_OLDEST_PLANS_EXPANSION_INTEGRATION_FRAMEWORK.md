# 2. Cross-Subsystem Unified Dependency Graph & Data Flow

To preserve the fundamental rule of **One Authority Per Concern**, interactions between the five systems are strictly governed by unidirectional fact flow and event contracts:

### 2.1 The Inter-System Narrative & Resource Bridge
1. **Plan 28 (Ecology) -> Plan 13 (Economy):**
   - Wildlife migration facts and predator-prey density indices generated by Plan 28 feed directly into Plan 13's wilderness trapping yields.
   - When Plan 28 registers prey overharvesting (`prey_hare` density drops below 200‰), Plan 13's caravan encounter tables dynamically inject predator ambushes, increasing overland travel risk.
2. **Plan 13 (Economy) -> Plan 22 (Production):**
   - Active market contracts in Plan 13 request heavy manufactured goods (e.g., cast iron wheel rims, structural beams), generating prioritized commission orders in Plan 22's foundry queue.
   - Preserved food batches produced by Plan 22's pickling and smoking pipelines feed Plan 13's long-distance expedition supply requirements.
3. **Plan 22 (Production) -> Plan 09 (Medical):**
   - Plan 22 greenhouse chemical distillations produce pharmaceutical precursors (`item_willow_salicin`, `item_poppy_laudanum`), which feed Plan 09's palliative comfort regimens and detox clinic taper schedules.
   - High-temperature blast cupola accidents or silica dust leaks in Plan 22 route trauma burns and respiratory conditions into Plan 09's diagnostic triage ledger.
4. **Plan 09 (Medical) -> Plan 06 (Narrative):**
   - Terminal palliative care completions in Plan 09 emit comfortable bereavement events, unblocking testamentary last letters in Plan 06's delivery ledger.
   - Deceased patients are archived into Plan 06's historical memorial records, awakening resilience traits in surviving kin.
5. **Plan 06 (Narrative) -> Global Escalation:**
   - Late-game faction war escalation permille (Day 480+) increases market tariffs in Plan 13, closes vulnerable trade routes, mandates defensive plating commissions in Plan 22, and mobilizes medical quarantine zones in Plan 09.

# 4. Save Store Architecture & Zero-Corruption Persistence Protocol

Every expanded system registers an independent, checksummed save section in `Assets/Ashfall.Core/Save/SaveSectionRegistry.cs`. This isolates state mutations, prevents monolithic save corruption, and guarantees full backward compatibility:

| System / Plan | Save Section Key | Section ID Pin | Primary State Types | Legacy Neutral Default |
|---|---|---|---|---|
| **Plan 06 (Narrative)** | `narrative_letters` | Section 267 | `LetterRecord[]`, `war_escalation_permille` | Empty ledger, 0 permille |
| **Plan 09 (Medical)** | `medical_clinical_depth` | Section 268 | `DiagnosticRecord[]`, `PalliativePatientRecord[]` | Empty infirmary, 0 patients |
| **Plan 13 (Economy)** | `economy_survival_loop` | Section 269 | `MarketContractRecord[]`, `TrapLineRecord[]` | Blank contracts, un-armed traps |
| **Plan 22 (Production)** | `production_commissions_preservation` | Section 270 | `CommissionProgressRecord[]`, `FoodBatchRecord[]` | Empty mold pits, raw food stocks |
| **Plan 28 (Ecology)** | `wildlife_ecology_depth` | Section 271 | `RegionObservationRecord[]`, `prey_densities` | Blank map signs, 1000‰ prey |

### Cryptographic Checksum Integrity
Each save section utilizes `SaveStoreHub.Checksummed<T>`:
1. State is serialized to compact, UTF-8 JSON.
2. Canonical SHA256 hash is computed over ordinal-sorted keys.
3. Envelope wraps state + checksum:
```json
{
  "section_id": "economy_survival_loop",
  "version": 1,
  "checksum": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "payload": { ... }
}
```
If a file suffers partial disk corruption, `SaveStoreHub` rejects the corrupted section and safely restores the backup envelope, preventing save game bricking.

# 5. Deterministic Simulation & Seed Replay Invariants

To guarantee 100% reproducible headless replays, the 5 systems adhere strictly to the **Seeded RNG Isolation Rule**:

- Every subsystem receives its own dedicated deterministic stream forked from the campaign seed:
  - `_campaignDay.Rng.Fork("narrative_depth")` (Plan 06)
  - `_campaignDay.Rng.Fork("medical_depth")` (Plan 09)
  - `_campaignDay.Rng.Fork("economy_loop")` (Plan 13)
  - `_campaignDay.Rng.Fork("production_decisions")` (Plan 22)
  - `_campaignDay.Rng.Fork("wildlife_ecology")` (Plan 28)
- **Zero Cross-Stream Contamination:** An extra dice roll in the medical triage system will never shift the seed alignment or weather crisis generation of the economy system.
- **Invariant Testing Gate:** All multi-day integration tests execute twice with identical seeds; the resulting save states must match byte-for-byte.

# 11. Cross-System Fuzzing & Resilience Protocol

To guarantee that no combination of player actions, resource shortages, or extreme weather states can crash the simulation, the five systems undergo automated stress fuzzing:

1. **Simultaneous Shortage Fuzzing:** The simulation is subjected to 500 consecutive ticks where inventory stocks of fuel, medicine, and food are set to absolute 0. The systems must handle starvation, pain escalation, and furnace freezing without raising uncaught exceptions.
2. **Corrupted Save Mutation Injection:** Random bit-flips are injected into the serialized JSON payloads of `narrative_letters`, `medical_clinical_depth`, and `economy_survival_loop`. `SaveStoreHub` must detect checksum mismatches 100% of the time, reject corrupted envelopes, and revert to safe default state.
3. **High-Stress Concurrency Soak:** 100 concurrent simulated days are executed in headless mode with 20 active survivors, 4 simultaneous foundry commissions, 8 wilderness trap lines, and active spore blooms. Total process memory must remain stable below 250 MB without unbounded memory creep.
