## Completed integration architecture

The shared direction is JSON authority → engine-free Core owner → thin Godot host adapter → current save-section owner → read-only panel. Cross-system effects flow through existing owner adapters and event facts. No document authorizes a parallel resource ledger, roster, clock, faction standing store, evidence ledger, or hidden panel authority. The exact production files and any schema change must be claimed in `WORKTREE_OWNERSHIP.md` for a promoted package.

The ten domain boundaries are specific. Duty assignment and overflow belong to `DutyRosterSystem` and its `duty_roster` save; Muster warfare belongs inside `MusterSystem` while standing and endings remain their separate authorities; Silent Foundry and powder metallurgy retain separate production state; maintenance and sanitation use their live Core/host/save owners. Heirloom instance persistence remains an explicit host census. Capsule persistence is live, while survivor letter delivery still needs a host and save decision. Accusation state already rides VerdictSave v4, so the open question is the player route and resulting adapter effects. Trade tells are presentation selected by `ITradeTellProvider`, not a price or save authority.
