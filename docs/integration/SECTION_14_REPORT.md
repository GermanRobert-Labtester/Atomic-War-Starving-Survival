### 3.D Path / loader contract investigation

The brief asked: **"Investigate whether Godot can use SVG assets vs the `.png` loader."**

**Answer (probe-driven):**

1. `src/Economy/TradeScreenGodotPanel.cs:529,590` and `src/Radio/FactionRadioHudPanel.cs:300` hard-code `.png` in the format string.
2. `Assets/UI/Icons/faction_icon_garrison.svg.import` proves that **Godot 4.7 DOES successfully import SVG into a `CompressedTexture2D`** (so SVG is technically consumable).
3. However, the existing loader contract is `.png`. **Changing it to "try .svg then .png" is architecture surgery** with three call sites — and "smallest architecturally correct solution" per brief 3.10 says: **do not rewrite a stable asset system to avoid four PNG conversions.**

**Resolution chosen:** Do not modify the loader. **Generate the missing PNG icons** (Section 7 deliverable: prompt cards + a tiny one-shot rasterizer script) OR supply a runtime alias file `Assets/UI/Icons/faction_icon_<systemsId>_alias.svg.import` so the import pipeline lands a `.ctex` that loaders can fetch via `LoadTexture` — *but Godot's `.import` files are auto-generated;* hand-authoring them violates the brief 9.12. So **the correct move is: produce PNGs from the canonical SVGs we already have ON DISK** for the lore-anchored sets (`garrison`, `militia`, `scavenger`, `warlord`, `cult_of_the_glow`), and **deliver a prompt package for the truly missing 20+ empirical systems emblems** (Section 7).
