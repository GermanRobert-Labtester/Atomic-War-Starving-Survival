## 9. Exactly three subfeatures

### 1. Curated opening cards with truthful constraints

Show a small library of distinct opening premises, what is known, which existing profile IDs they select, and what the player cannot change. Never promise a guaranteed route, item or event absent from those catalogs. Authority boundary: Scenario definition is immutable selection metadata; cohort, supplies, difficulty and world generation owners each validate their own stable IDs before fresh slot allocation.

### 2. A constrained opening built from existing profiles

Make each opening feel different through valid composition of current cohort, supplies, difficulty and optional existing opening quest references. Declare the source of every pressure so the player can compare rather than guess. Authority boundary: Starting profile catalogs and XP W1 difficulty owner validate the chosen IDs; scenario mapping does not copy mutable values or apply hidden bonuses.

### 3. Carry an opening into the run and debrief

Let the authored premise appear in the existing opening briefing and return in a factual end-of-run debrief using already recorded campaign events. Do not create a new objective manager, completion flag graph, score or unlock currency. Authority boundary: Existing quest choices and campaign history determine what happened; CampaignCompletionHistory and ChroniclePanel remain the debrief history owners. Scenario metadata is only an approved label/source reference.
