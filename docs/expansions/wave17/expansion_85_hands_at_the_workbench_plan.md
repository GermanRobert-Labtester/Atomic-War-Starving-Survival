## 8. Player-to-state flow

The player opens the existing route, reads source-backed current state, chooses one of the feature's explicit commands, confirms against refreshed state, and receives a result from the owning command. The host translates that result into presentation and persistence effects exactly once. On cancellation, stale state, failed validation or a closed panel, no speculative mutation is shown as success. The three subfeature flows are separately mapped: 1. Trace a weak transmission by hand → 2. Isolate a circuit with a readable trace → 3. Work salvage locks accessibly.

## 9. Exactly three subfeatures

### 1. Trace a weak transmission by hand

Offer an optional drag/tune gesture over the existing radio signal display, then commit the same station/frequency command the current tuner accepts. Keep the existing direct controls available as an equal path. Authority boundary: RadioTuner and its host session own tuned frequency, signal truth, discovery and any campaign result; RadioIntelligencePanel only visualizes samples and emits the existing command.

### 2. Isolate a circuit with a readable trace

Layer a short, optional diagram trace over existing breaker controls so players can inspect the affected room and confirm one existing ToggleBreaker command. Preserve the standard panel list and direct input. Authority boundary: PowerGridSystem owns breaker state and network consequences; PowerGridHostSession applies the same command and result as the present panel.

### 3. Work salvage locks accessibly

Present the existing accessible safe attempt as an optional tactile read/confirm sequence that previews control meanings and then calls AttemptAccessible once. The current accessible input remains usable without the sequence. Authority boundary: SafeCrackingSystem and MaritimeHostSession own skill, tools, seeded result, accessible confidence input and consequences; this surface explains, confirms and displays returned feedback only.

## 10. State and command contract

1. Trace a weak transmission by hand: use stable IDs, validate against the current source owner immediately before commit, make repeated UI delivery idempotent where the domain permits, and return an explicit accepted/refused/stale outcome. Required visible postcondition: only the accepted tuner command changes radio state; waveform art never creates a station, discovery, reward, or misleading confidence. Forbidden shortcut: Gesture release is a request. The Core tuner result is the only outcome. No reflex window, invented frequency precision or input-device advantage is permitted.

2. Isolate a circuit with a readable trace: use stable IDs, validate against the current source owner immediately before commit, make repeated UI delivery idempotent where the domain permits, and return an explicit accepted/refused/stale outcome. Required visible postcondition: the command targets exactly one current room ID and shows the owner's returned state; the trace cannot route power, prioritize loads, or bypass existing electrical rules. Forbidden shortcut: No second grid graph, custom circuit state, hidden success rule or free power adjustment is added. The diagram is a learning surface, not an authority.

3. Work salvage locks accessibly: use stable IDs, validate against the current source owner immediately before commit, make repeated UI delivery idempotent where the domain permits, and return an explicit accepted/refused/stale outcome. Required visible postcondition: one owner-accepted attempt yields the existing seeded result; a cancelled gesture spends no attempt and cannot reroll or improve chance. Forbidden shortcut: The interaction may not punish motor speed, require audio-only cues, expose hidden RNG, bypass locks or create a separate tool-wear ledger.
