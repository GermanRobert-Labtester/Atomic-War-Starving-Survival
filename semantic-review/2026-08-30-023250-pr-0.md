# Cross-wave campaign persistence and lifecycle authority

The working diff adds lifecycle-group metadata and alias normalization, tightens current campaign-envelope validation, stages required projection reconciliation, and moves host-event capture toward the adapter-owned ledger. The save path still has a split boundary: required sections are written directly outside the campaign payload map, while the capture map and commit result remain long-lived and unchecked. The lifecycle reset is non-destructive in isolation, but the fresh-game wrapper no longer removes the active slot-root campaign, and slot restore still reuses live session instances. **Watch for:** **[confirmed]** `StartNewGame()` can reopen the previous slot-root campaign; **[confirmed]** normal saves can create orphaned required projections for PowerGrid, MedicalWard, and ShelterAssignment; **[confirmed]** stale captures and ignored commit results can report a save that did not commit; **[confirmed]** the event adapter and broader session graph are not rebound on slot changes. **Verdict**: NEEDS_CHANGES

## High-level view

`Main.SaveAll()` still accumulates section bytes in `_sectionPayloads` before `SaveLoadHostSession.SaveEnvelopeFromPayloads()` commits `campaign.json`. The map is not a per-save-generation object, failed keys are retained, and the caller does not consume the commit Boolean, so the envelope cannot guarantee a fresh, acknowledged snapshot.

Load/unpack validates the campaign envelope and stages derived files before exposing a new root. Current V2 identity/generation presence and legacy projection cleanup are covered by the working diff, but the required-orphan guard exposes direct writers that never enter the envelope; V1 metadata and zero-restorable-section semantics remain asymmetric.

The lifecycle group is metadata-only and does not add an `expanded_shelter` section, while production aliases use the canonical `expansion_hub`, `expedition`, and `caravan` keys. Runtime ownership still diverges from that declaration: faction-branch state is omitted from the group reset, ShelterAssignment writes outside aggregate capture, and `host_event` has no participant that can dispose or rebind its adapter.

Slot selection changes the root before load, and rollback can restore that root on a failed target load. It does not restore already-constructed domain sessions, so a successful A→B load can leave A's state in memory while B's projections are active; a save before load completion can write A's payloads under B.

The working tree has twelve unstaged source modifications and an untracked review directory; no source/test changes are staged. Three files introduced by the HEAD Task #131 commit are modified here, although its composition-root files/test remain unchanged. UtilityAI paths are untouched, but the six-action catalog still meets a four-action UI assertion, leaving that known gate mismatch for separate coordination.

### Fresh-game reset leaves the campaign authority alive [confirmed, current-wave regression]

`StartNewGame()` calls `ResetAllSessions()`, which calls `ResetAllSessionsInMemory()` and then `DeleteGlobalSavesOnDisk()`. The in-memory reset clears `_sectionPayloads` and the capture latch, and the expanded-shelter callback no longer deletes files. `DeleteGlobalSavesOnDisk()` only removes registry filenames from the globalized `user://` directory; it does not remove the active slot root, `campaign.json`, `manifest.json`, backups, or slot projections under `saves/profile-*/slot-*`.

The next line selects or creates `slot_1`. If that directory exists, `SelectOrCreateDefaultSlot()` calls `SelectSlot()` instead of creating a clean slot. `ComposeCampaign()` then invokes guarded setup methods that load from the still-active root. The current diff can therefore reconstruct the previous campaign in a new-game flow. A terminal or corrupt slot can make selection fail while leaving the old root active. The explicit new-campaign policy must delete/recreate the selected slot or allocate a new one without moving deletion into the reusable in-memory reset.

### Required derived files still have writers outside `campaign.json` [confirmed, baseline callers exposed by current guard]

`SaveAll()` calls `SavePowerGrid()` before the aggregate write; `_powerGrid.TrySave()` writes `power_grid_save.json` on every save, but no `CaptureSection("power_grid", ...)` call exists. The same pattern remains for `SaveMedicalWard()` calling `MedicalWardHostSession.Save()` and `SaveShelterAssignment()` calling `ShelterAssignmentHostSession.Save()`. Their stores can write `medical_ward_save.json` and `shelter_assignment_save.json`, but those bytes never enter `_sectionPayloads`.

The current `TryProjectEnvelope()` loop treats a required file missing from the envelope as an out-of-generation projection and fails the load before subsystem restore. A normal save can therefore be followed by load failure once one direct writer has produced its file; an aggregate failure also cannot roll the direct file back. The direct callers predate this working diff; the required-orphan guard is current-wave code that makes the divergence fail closed. Each registry key needs one persisted capture path, with direct projection writes reserved for unpack.

### The capture map is not a save-generation boundary [confirmed, pre-existing W1 blocker]

`_sectionPayloads` is constructed once and is cleared only by `ResetAllSessionsInMemory()`. `SaveAll()` does not clear it before capture, and `SelectSlot()` does not clear it when changing roots. `CaptureSection()` overwrites a key only after a non-empty capture; an empty capture sets `_sectionCaptureFailed` but leaves an earlier payload. A failed standalone flush can poison the next full save, and an uninitialized section in a later slot can leave prior-slot bytes available for emission.

`SaveAll()` plays the success cue before checking `_sectionCaptureFailed`, then calls `_saveLoadHost?.SaveAllDirect(_sectionPayloads)` without inspecting its Boolean. `SaveEnvelopeFromPayloads()` can refuse a missing slot, invalid envelope, builder rejection, or atomic-write failure while the caller reports no failure. `SaveJournal()`, `SaveMoralChoice()`, `SaveExpansionQuests()`, `SaveThirdonary()`, and `SaveMedicalWard()` also clear dirty state without consistently requiring successful capture/write. A per-save capture context and a commit result propagated to UI/dirty state are release prerequisites.

### Slot-root rollback does not rebind domain state [confirmed, pre-existing cross-wave blocker]

`SelectSlot()` captures a rollback snapshot, changes `_activeSlotId`, clears `_activeEnvelope`, applies the new `SaveSlotRoot`, and emits `ActiveSlotChanged` before load. `TryLoadSlot()` now restores that snapshot on failure and emits the inverse event for the matching target, closing the earlier silent-observer gap. The snapshot remains root/envelope bookkeeping; it does not reset or restore `Main` domain objects.

`TryLoadAndRestoreGame()` calls `TryLoadSlot()` and then `RestoreAllSubsystemsFromDisk()`. Every setup method is guarded, so a live A→B load retains existing survivor, inventory, calendar, narrative, and other instances instead of reading B's projected files. The same window exists after `SelectSlot(B)` and before `Load Selected`: `SaveAll()` can write current A instances through B's root. The rollback helper is also one-slot state; a later selection or direct load for another target can supersede or clear the pending transaction. Selection must not expose a new root to saves until load/rebind succeeds, and successful load needs an explicit reset/recomposition phase.

### Host-event state has no complete lifecycle lease [confirmed, current W3 gap]

`SaveSectionRegistry` contains only the canonical `host_event` key, and `EventsHostSession` remains a catalog/read-model node, so there is no second mutable event ledger. The adapter-owned state is defensively copied, and `SaveEventAdapter()` captures `CaptureState()` through the persisted store.

The lifecycle registration gives `narrative_radio` only the `narrative` key. Its reset callback sets `_hostEventAdapterDirty = false` but never nulls or disposes `_hostEventAdapter`; `HostEventAdapter` has no unsubscribe/dispose operation for its four bus handlers. `SetupNarrative()` now calls `SetupEventAdapter()`, but that method returns when the adapter exists. After A→B selection or a new-game reset, old triggered IDs and event-trigger days remain active, and the next `host_event` capture can publish them under B. Rebind after active-slot acceptance and before day-owner evaluation, removing old subscriptions before constructing the replacement.

### Expanded-shelter group metadata does not enforce ownership [confirmed, current W4 gap]

The new `LifecycleGroup` is absent from `SaveSectionRegistry.All` and `SectionFileNames`, so it does not create an `expanded_shelter` envelope key or projection. The three historical labels are canonicalized in production lifecycle registrations, and `OwnedSaveSectionKeys` derives group keys from existing metadata.

The runtime callback is incomplete. `SaveAllExpandedShelterSystems()` calls `SaveFactionBranch()`, and the registry assigns `weight_of_choices` to the expanded group, but `ResetExpandedShelterSessions()` never disposes/nulls `_factionBranch` or clears `_factionBranchDirty`. `SetupFactionBranch()` consequently reuses the prior coordinator after `StartNewGame()`. ShelterAssignment is also listed in the group but still uses direct `Save()`, so the group describes ownership the capture graph does not implement. The registry needs a one-owner/one-capture/one-reset invariant rather than metadata-only grouping.

### Terminal policy mutates the slot while answering a question [confirmed, current-wave regression]

`IsIronManTerminal()` routes any existing `campaign.json` through `TryLoadAggregate()`. Invalid data is quarantined by moving the campaign to a `.corrupt` path and deleting the original. `SelectSlot()` and `DeleteSlot()` call this helper as a policy probe, so a read-only card/selection/deletion check can mutate the slot.

After quarantine, `LoadManifest()` sees no aggregate and falls back to `manifest.json`. If that projection is stale and non-terminal, later card/continue calls can display an ordinary slot even though the authoritative campaign was rejected, while the immediate policy call blocked it. Use a non-quarantining policy read or an invalid-authority marker that prevents manifest fallback until recovery.

### V1 remains asymmetric after current V2 hardening [confirmed, current-wave residual]

Current envelopes require non-empty manifest and section generation IDs and non-empty profile/slot IDs, and current writes compare those identities with the requested slot. `LoadManifest()` and `WriteAggregateAtomically()` have no equivalent requested-target check for V1. A checksum-valid V1 envelope copied to another slot can supply foreign metadata to slot cards, and a direct V1 write can be accepted even though migrated restore later rejects its identity.

The migration branch logs, but does not fail, when `MigrateToCurrent()` produces zero known/reserved sections. `TryLoadAggregate()` then returns `SaveLoadResult.Ok`; `TryProjectEnvelope()` rejects the same envelope because it has no projections. Core and host callers therefore disagree about whether an all-stray legacy slot loaded successfully. Return one no-restorable-section result before terminal policy, deletion, or host projection.

### Generation checks are labels rather than integrity fields [confirmed, residual W2 blocker]

`ValidateAggregate()` requires a current manifest generation and a non-empty section generation matching it. `ComputeSectionChecksum()` still hashes only section name, schema version, and payload; `ComputeAggregateChecksum()` hashes manifest fields and section name/version/checksum/payload but omits both generation values. A stale section can be relabeled with the current generation and have the aggregate checksum recomputed without changing its section checksum or payload. Include generation in both canonical forms and add a relabel/tamper gate.

### Derived projection rollback remains vulnerable to process death [confirmed, residual W2 risk]

`TryProjectEnvelope()` now includes `legacy.json` in stale cleanup and rejects required orphan files before staging. It writes desired projections to a temporary directory, moves them one at a time into the slot root, deletes stale files, and rewrites originals only when an exception is caught. A process termination between moves bypasses compensating rollback and leaves a mixed directory. `campaign.json` remains the intended authority, but a compatibility reader before repair can observe a partial projection. Add a transaction marker or versioned projection directory with deterministic recovery if projections are a runtime contract.

### Scope and validation gates [confirmed]

The working diff has no staged index entries; all twelve source modifications are unstaged, with review reports untracked. HEAD is Task #131, and the working diff overlaps its save-path files (`SaveEnvelopeHelper.cs`, `SaveSlotService.cs`, `SaveLoadHostSession.cs`) even though it does not touch `Main.CampaignServices.cs`, `Main.UiTests.CompositionRoot.cs`, or `CompositionRootArchitectureGateTests.cs`. Whether this violates “protected Task #131 paths” depends on whether protection covers the entire commit path set or only the composition-root subset.

The UtilityAI data still has six definitions (`action_weigh_goods`, `action_read_contract`, `action_canvas_support`, `action_run_vouch`, `action_audit_inventory`, and `action_file_report`), while `Main.UiTests.UtilityAi.cs` still checks `_utilityAi.Actions.Count == 4`. No current diff path touches the data, Core UtilityAI, panel, or UI smoke test. The mismatch is preserved as requested, but any mandatory UI smoke gate remains expected to fail until its owner decides which count is authoritative.

No current test changes exercise the complete capture→commit→projection→restore sequence, direct required stores, fresh-game slot isolation, adapter rebind, group reset completeness, V1 identity/empty migration, or generation relabeling. The Task #131 composition gate proves that `StartNewGame()` calls `ComposeCampaign()` and setup guards are idempotent; it does not prove that preserved state belongs to the selected campaign. Add these gates only after ownership and transaction boundaries are corrected.
