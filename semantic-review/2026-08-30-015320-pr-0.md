# Campaign envelope authority and rollback hardening (W2)

This diff makes `campaign.json` the preferred manifest source, revalidates the temporary aggregate payload before replacement, adds current/V1 identity handling, and stages derived section projections with rollback. Several authority boundaries remain permissive, and the excluded orchestrator still writes state outside the aggregate. **Watch for:** **confirmed** V2 identity and terminal-policy bypasses in Core, **confirmed** stale legacy projection and silent selection rollback in the lease, and **confirmed** PowerGrid/capture-map integration defects outside the lease. **Verdict**: NEEDS_CHANGES

## High-level view

The Core authority boundary still accepts empty current-format identities, trusts an unvalidated terminal manifest, and treats generation IDs as optional and non-integrity-covered (**confirmed**).

The host projection transaction restores the previous root on load failure but leaves the reserved `legacy.json` projection outside stale-file reconciliation and does not notify listeners when a failed selection is reverted. V1 envelopes containing only dropped sections can also be reported as successful even though the host cannot project them (**confirmed**).

The excluded Main orchestration writes PowerGrid state before the aggregate commit, retains captured payloads across resets, and ignores the commit result. Those paths can create a required derived file without a campaign section or carry a prior campaign into a later save; the existing test/self-test paths do not pin these cases (**confirmed**).

<summary>Details</summary>

### V2 identity remains optional at the authority boundary (confirmed)

`ValidateAggregate` contains a V2 identity block that performs no validation (`Assets/Ashfall.Core/Save/SaveSlotService.cs:355-360`). The slot-aware load checks only reject non-empty mismatches (`:562-583` and `:621-644`), so a V2 envelope whose deserialized `SaveProfileId`/`SaveSlotId` is default or empty can be accepted and projected into any requested slot. `WriteAggregateAtomically` validates shape and checksums but never compares the envelope identity with its `profileId`/`slotId` arguments (`:400-455`).

The new `LoadManifest` authority path is also missing the requested-path comparison: after validating `campaign.json`, it returns `aggregate.manifest` directly (`:203-225`). A copied, checksum-valid envelope with a foreign non-empty identity is rejected by `TryLoadAggregate`, but `GetManifest`/slot-card callers can still display that foreign manifest before a load attempt. The fix needs one explicit current-format identity contract shared by load, manifest lookup, and write; V1 may remain permissive only until it is mapped to a requested profile/slot.

### Terminal policy does not validate campaign.json (confirmed)

`IsIronManTerminal` now fails closed for empty or unparsable campaign data, but for any deserializable object with a manifest it returns `ironManTerminalState` without calling `ValidateAggregate` (`Assets/Ashfall.Core/Save/SaveSlotService.cs:798-817`). A checksum-invalid or identity-invalid envelope whose manifest says `Active` therefore passes the deletion/selection gate even though `TryLoadAggregate` would reject it. Since `DeleteSlot` uses this helper, corruption can remove a terminal archive instead of preserving it. The terminal decision must consume the same validated authority as restore and treat checksum, version, identity, and section failures as blocked/indeterminate.

### Generation identity is not integrity-covered (confirmed)

The mixed-generation check only runs when both the manifest and section IDs are non-empty (`Assets/Ashfall.Core/Save/SaveSlotService.cs:339-347`). A V2 section can omit its ID and still pass. More importantly, `ComputeSectionChecksum` canonicalizes only name, schema, and payload (`:1004-1007`), while `ComputeAggregateChecksum` canonicalizes section name/version/checksum/payload but not section generation IDs, and its manifest field list does not include `manifest.generationId` (`:1030-1060`). The claimed generation boundary can therefore disappear or change without invalidating the envelope. V2 validation should require the fields and the canonical forms should include them; migration should deliberately stamp or preserve a valid generation.

### V1 migration has an invalid-success branch (confirmed)

`MigrateToCurrent` can drop every unknown V1 section. `TryLoadAggregate` detects that the migrated envelope is invalid, but only returns failure when `envelope.sections.Count > 0`; for the zero-section case it logs a warning and falls through to `SaveLoadResult.Ok` (`Assets/Ashfall.Core/Save/SaveSlotService.cs:590-610, 654`). `TryLoadSlot` then rejects the same object because `TryProjectEnvelope` requires at least one section. This gives Core callers a successful result whose envelope fails its own current-format validation and makes legacy-only behavior differ between service and host. A reserved `legacy` section should remain supported, but a V1 envelope with no known/reserved section should have one consistent failure result.

### Derived projection reconciliation misses legacy.json (confirmed)

The host maps the reserved `legacy` section to `legacy.json` (`src/Host/SaveLoadHostSession.cs:664-667`), but stale discovery iterates only `SaveSectionRegistry.All` (`:695-713`) and then the in-memory `_restoredSections` set (`:718-723`). If a slot was previously loaded from a legacy import and later receives a non-legacy envelope, `legacy.json` is neither desired nor stale and remains on disk. That leaves a derived payload from an older generation outside the transaction. Add the reserved file to the same stale-file and original-content sets used for registry sections.

### Selection rollback restores state without restoring observers (confirmed)

`SelectSlot` emits `ActiveSlotChanged` for the new slot before its load is attempted (`src/Host/SaveLoadHostSession.cs:178-183`). On failure, `RestoreSelectionAfterFailedLoad` restores `_activeSlotId`, `_activeEnvelope`, `_restoredSections`, and `SaveSlotRoot.CurrentRoot`, then clears its snapshot without raising the inverse event (`:856-892`). UI/session listeners can therefore continue to believe the failed slot is active even though stores write under the prior root. The snapshot is also not tagged with the slot it was created for, so a direct `TryLoadSlot` call for a different slot can restore an older selection. Make the rollback conditional on its target and emit the active-slot change when the prior selection is reinstated.

### Excluded Main orchestration remains outside the campaign transaction (confirmed)

`SaveAll` calls `SavePowerGrid` before the aggregate commit (`src/Main.SaveOrchestrator.cs:229-258`), while `SavePowerGrid` calls `_powerGrid.TrySave()` directly (`src/Main.World.cs:254-265`). The registry marks `power_grid` as a required section (`Assets/Ashfall.Core/Save/SaveSectionRegistry.cs:60,139`), and the new projection scan fails closed when a required derived file exists without an aggregate section (`src/Host/SaveLoadHostSession.cs:695-712`). The normal save sequence can therefore create the stale required-file state that the lease-local loader rejects, and an aggregate failure cannot roll back the direct PowerGrid write.

The capture dictionary is initialized once and only overwritten when a capture call succeeds (`src/Main.SaveOrchestrator.cs:41-64`); `ResetAllSessions` does not clear it (`:85-89`). `SaveAll` likewise does not establish a fresh capture generation and ignores the boolean from `SaveAllDirect` after playing the success cue (`:197-258`). A new run or an absent optional subsystem can inherit old payload bytes, while a failed aggregate commit is presented as a successful save. These require excluded Main/host-store changes rather than another Core validator tweak.

### Regression coverage gap (confirmed)

The local diff changes Core authority, migration, terminal gating, and host projection/rollback without changing `Ashfall.Core.Tests` or the Godot save/load failure self-test. Existing coverage exercises ordinary V1 migration and basic malformed/checksum failures, but does not pin the newly added edge behavior listed above. The missing gates are an excluded test-path blocker, not a reason to edit tests within this review.
