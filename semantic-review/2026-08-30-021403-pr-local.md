# Campaign-backed host event ledger and catalog boundary

W3 moves host event progress behind an adapter-owned state snapshot, keeps `EventsHostSession` as a catalog/read model, and routes `host_event` through the checksummed campaign capture path. Mutation sites target `HostEventAdapter`, while the Events UI consumes catalog projections rather than a second ledger. **Watch for: confirmed — the eager setup is construction-only, so loading or switching slots in a live process can retain the previous adapter state; the lifecycle omission enabling this is pre-existing, but it blocks W3’s restore guarantee.**

**Verdict**: NEEDS_CHANGES

## High-level view

The ownership boundary is explicit: `HostEventAdapter` owns mutable progress; `EventsHostSession` owns catalog lists and getters. `SaveSectionRegistry` has `host_event` but no `events` key—the `Owner` value `events` is metadata, not another persisted section.

The save direction is envelope-first. `SaveEventAdapter()` snapshots with `CaptureState()`, serializes through `HostEventSaveStore.TryCapturePersisted()`, and passes the result to `CaptureSection()`; no current caller invokes the store’s direct `TrySave()` API.

**Confirmed**: `SetupNarrative()` now calls `SetupEventAdapter()`, but the adapter’s non-null guard prevents rereading the projected `host_event_save.json` after a slot change. The catalog path and hard-coded dynamic event definitions are **confirmed, pre-existing** issues outside the W3 behavior diff.

<summary>Details</summary>

### One mutable host-event authority

`HostEventsDayOwner` evaluates the day predicates through `HostEventAdapter`; the Muster and Crossing callbacks also call that adapter for their event IDs. `EventsHostSession` exposes no trigger ledger, `CaptureState`, `RestoreState`, or save call. The registry maps the single relevant key, `host_event`, to `host_event_save.json`; no `events` section forks persistence.

The adapter now allocates its own `HostEventState` and copies restored lists and dictionary entries into it. `CaptureState()` copies both collections again. `Main.Narrative` then sends that snapshot through `HostEventSaveStore.TryCapturePersisted()` and `CaptureSection("host_event", ...)`. A repository-wide call-site trace found `HostEventSaveStore.TrySave()` only as an API definition, not as a current write path.

### Slot-switch restore is construction-only

The W3 call is made after the narrative session’s null check, but the adapter setup remains guarded:

```text
SetupNarrative()
  if (_narrative == null) create narrative
  SetupEventAdapter()
    if (_hostEventAdapter != null) return
    load HostEventSaveStore from current slot root
```

**Confirmed**: `RestoreAllSubsystemsFromDisk()` invokes `SetupNarrative()` after `SaveLoadHostSession.TryLoadSlot()` projects the selected campaign. The first composition reads the projected event payload. A later slot selection changes the root, but `_narrative` and `_hostEventAdapter` are already live, so the guard returns before reading slot B. The adapter can suppress B’s events using A’s IDs, and the next capture can place A’s ledger in B’s aggregate.

The reset path has a related **confirmed, pre-existing** lifetime gap: `Main.Lifecycle` resets `_hostEventAdapterDirty` but never nulls or disposes `_hostEventAdapter`, and `HostEventAdapter` has no unsubscribe/dispose method even though `IEventBus` supports `Unsubscribe`. Rehydrate the existing adapter after every successful slot restore, or dispose/unsubscribe it and construct a fresh adapter when the active campaign changes; clear the dirty flag only after the new state is installed.

### Catalog/read-model path remains outside the W3 behavior change

The Events UI binds to `GetRecentEvents()`, `GetIncidents()`, and `GetNarrativeProgression()`, which are catalog projections rather than triggered-event history. That preserves the no-fork boundary. The catalog loader itself has a **confirmed, pre-existing** path defect: `EventsHostSession.LoadEvents()` unconditionally passes a `res://` path to Core `FileSystemIO`, and its incident/narrative existence checks use the same adapter. In Godot, this bypasses the virtual filesystem and can leave the UI empty or raise during `_Ready`; the W3 diff changes only comments around this code.

The adapter’s dynamic behavior is also **confirmed, pre-existing** and not catalog-driven: its constants and prose handlers are in host code, and fallback thresholds are literals. Matching IDs and day values exist in `year_of_ash_events.json`, but no `YearOfAshCatalogLoader.LoadEvents()` result reaches the adapter. This is an authority split, not a new W3 persistence section.

### Durability and validation boundary

The campaign path remains envelope-first: section capture produces persisted bytes, `SaveAllDirect()` builds one registry-keyed envelope, and the slot service validates and writes `campaign.json`. The adjacent save-service validation and projection rollback changes do not create a host-event special case.

The deferred durability is a **confirmed, pre-existing** shared behavior: after an event dispatch, `_Process` can capture into `_sectionPayloads` without committing the aggregate until the next `SaveAll`. A crash in that interval can lose the event even though capture succeeded. Choose the durability boundary explicitly; the fix should not be a direct `HostEventSaveStore.TrySave()` call from the adapter.
