# W2 aggregate authority, generation integrity, and fail-closed loading

W2 makes `campaign.json` the preferred campaign authority, validates the serialized candidate before aggregate replacement, and stages derived section projections before publishing a loaded slot. The host also distinguishes explicit empty captures from omitted optional sections, and V2 identity/generation presence plus required orphan projections are checked on the normal paths. The remaining gaps are concentrated at the V1 boundary and at read-only selection/policy consumers rather than in the basic candidate-write path. **Watch for:** **confirmed** generation IDs are not covered by either checksum; **confirmed** V1 metadata and writes can bypass requested-slot identity; **confirmed** an all-stray V1 migration reports success; **confirmed** terminal inspection can quarantine an aggregate and then expose stale manifest metadata; **confirmed** rejected slot selection can leave the UI and active root divergent; **confirmed** projection rollback is not crash-atomic. **Verdict**: NEEDS_CHANGES

## High-level view

The V2 path has a coherent authority direction: captured payloads feed `campaign.json`, current identities are checked, the serialized candidate is validated before replacement, explicit empty required captures abort, optional empty captures are omitted, and `legacy.json` participates in projection cleanup. **confirmed** caveat: the generation value tying these checks together is still metadata rather than authenticated save content.

The V1 compatibility path remains permissive where current restore is strict. **confirmed** `LoadManifest` can return a foreign V1 manifest and `WriteAggregateAtomically` can emit a foreign V1 envelope, while a later migrated load rejects the non-empty identity mismatch. **confirmed** a V1 envelope whose sections are all registry strays is returned as a successful Core load even though host unpack rejects it.

Terminal policy is routed through aggregate validation, but **confirmed** that route is destructive because the loader quarantines the aggregate; later metadata reads can then expose the stale manifest-only fallback. **confirmed** the save panel records a requested slot before checking whether `SelectSlot` accepted it, so a fail-closed rejection can leave the display pointing at a slot whose root is not active.

The campaign replacement is atomic for the current `FileSystemIO` path and invalid candidates cannot replace the prior campaign. **confirmed** the derived projection operation is a sequence of file moves with compensating rollback, not an atomic directory swap; a process failure during that sequence can leave compatibility files mixed until reconciliation.

<summary>Issues (7)</summary>

1. **P1 — Generation IDs are outside checksum coverage (confirmed)** — Require and match generation IDs as done today, but also include the manifest and section generation values in their canonical checksums; otherwise stale payloads can be relabeled as the current generation without invalidating the envelope.
2. **P1 — V1 identity is asymmetric (confirmed)** — `LoadManifest` and `WriteAggregateAtomically` do not enforce the requested profile/slot for V1 even though migrated restore does; define the V1 identity rule and make read/write paths use it consistently.
3. **P1 — All-stray V1 migration reports success (confirmed)** — A V1 envelope that migrates to zero known/reserved sections reaches `SaveLoadResult.Ok`; return a failure/empty-envelope result before terminal policy or host unpack sees it.
4. **P1 — Terminal inspection reopens stale manifest authority (confirmed)** — `IsIronManTerminal` calls the quarantining loader, then later reads can fall back to `manifest.json`; use a non-quarantining validation path or persist an invalid-campaign marker that blocks manifest fallback.
5. **P1 — Rejected selection can desynchronize the save UI (confirmed)** — The panel and Main callback ignore `SelectSlot` failure, and the pending rollback snapshot is discarded on an unrelated direct-load target; update selection only after acceptance and preserve/identify rollback transactions correctly.
6. **P2 — Projection commit is compensating rather than crash-atomic (confirmed)** — The campaign remains authoritative, but multi-file derived projections can be left mixed by a process crash; add a directory-swap/recovery marker or make the next load deterministically repair every interrupted projection.
7. **P2 — New W2 edge paths lack regression gates (confirmed)** — Existing coverage exercises ordinary V1 migration and basic corruption but not generation tampering, foreign V1 metadata, all-stray migration, quarantine/fallback behavior, or rejected-selection rollback; add those gates before depending on these contracts in W3/W4.

<summary>Details</summary>

### V2 generation identity is a label, not an integrity field (**confirmed**)

`ValidateAggregate` now requires a non-empty manifest generation and a non-empty section generation matching it (`Assets/Ashfall.Core/Save/SaveSlotService.cs:300-368`). The two checksum canonical forms do not cover those fields: `ComputeSectionChecksum` hashes only section name, schema version, and payload (`:1024-1025`), while `ComputeAggregateChecksum` hashes manifest fields and each section's name, version, checksum, and payload but omits both generation values (`:1047-1077`).

That lets a stale section be relabeled without invalidating either checksum. Starting from a valid envelope, changing the manifest and section generation IDs to the same new value and recomputing the aggregate checksum leaves the section checksum valid and makes `ValidateAggregate` accept the envelope, even though no authenticated evidence ties the payload to that generation. Add both generation values to the canonical forms and explicitly recompute/preserve them during V1 migration.

### V1 identity is not consistent across metadata, write, and restore (**confirmed**)

The new `LoadManifest` authority branch validates a V1 envelope but only compares embedded identity when the envelope is already current (`Assets/Ashfall.Core/Save/SaveSlotService.cs:203-238`). A checksum-valid V1 campaign copied into another slot can therefore supply that slot's UI card with the foreign campaign name, day, and IDs. `WriteAggregateAtomically` likewise applies its exact profile/slot check only to V2 (`:449-458`), so a direct V1 caller can successfully emit an envelope that the same service will later reject after migration (`TryLoadAggregate`: `:642-663`).

Keep V1 load leniency only where it is required for a documented legacy shape; when profile or slot identity is present, compare it with the requested path in `LoadManifest` and require the target identity for new writes. The import path already supplies target IDs, so this does not require abandoning legacy payload migration.

### All-stray V1 migration has an invalid success branch (**confirmed**)

After `MigrateToCurrent`, the service validates the migrated envelope but returns failure only when the migrated list still has entries (`Assets/Ashfall.Core/Save/SaveSlotService.cs:613-630`). A V1 envelope containing only unknown registry strays produces zero sections, logs a warning, and falls through to `return SaveLoadResult.Ok` at `:675`. The host then rejects the same result in `TryProjectEnvelope` because it has no section projections (`src/Host/SaveLoadHostSession.cs:640-643`).

This is not just a message mismatch: `IsIronManTerminal` sees the false Core success and can permit deletion of an active all-stray slot, while a slot card can display the V1 manifest as a valid save. Return `EmptyEnvelope` or `CorruptData` for zero restorable sections before terminal policy and host projection run; preserve success only for a known section or the reserved `legacy` section.

### Terminal policy has a destructive read and then loses the authority boundary (**confirmed**)

`IsIronManTerminal` now delegates to `TryLoadAggregate` (`Assets/Ashfall.Core/Save/SaveSlotService.cs:823-836`) so invalid campaign data is fail-closed for that immediate call. `TryLoadAggregate` quarantines malformed, checksum-invalid, and identity-invalid `campaign.json` files (`:527-574`, `:599`, `:657`), physically removing the file. On the next metadata read, `LoadManifest` sees no aggregate and returns the compatibility `manifest.json` at `:243-253`.

A read-only SELECT or DELETE check can therefore mutate the slot and make stale manifest metadata visible to `BuildSlotCard`/`UpdateContinueButton`; a corrupt active campaign can appear as an empty or continuable manifest-only slot after the policy probe. Keep quarantine in an explicit recovery/load operation, or record the quarantined-authority state so all later metadata and destructive-policy calls remain blocked rather than treating the stale projection as a fresh empty slot.

### Failed slot selection still has a caller-level divergence (**confirmed**)

`SelectSlot` returns false before changing the active slot when terminal policy or an invalid campaign blocks selection (`src/Host/SaveLoadHostSession.cs:168-179`). The panel sets `_selectedSlotId` before invoking the event (`src/UI/SaveLoadPanel.cs:122-126`), and Main ignores the boolean result (`src/Main.UiPanels.cs:395-399`). No `ActiveSlotChanged` event is emitted for that rejection, so the panel can show slot B as selected while the host remains on slot A; its SAVE CURRENT action is then still enabled against a different active root.

The new rollback code also clears its snapshot when a direct load for another target fails (`src/Host/SaveLoadHostSession.cs:885-889`), despite the comment saying that operation must not consume the pending snapshot. Make selection acceptance observable to the UI and keep rollback state associated with an operation token/target until the original selection either succeeds or is explicitly superseded.

### Derived projection rollback is not a crash-atomic slot commit (**confirmed**)

`TryProjectEnvelope` stages payloads, then moves each desired file one at a time (`src/Host/SaveLoadHostSession.cs:766-770`) and restores originals only in a catch block. A process termination between moves, or during rollback, leaves the slot's derived files in a mixed state; rollback failures are merely appended to the error list (`:801-804`). The aggregate remains authoritative and `TryLoadSlot` does not publish the new active envelope until projection returns, which limits the damage to compatibility files, but it does not provide strict multi-file slot atomicity.

If these projections must be immediately consumable after an interrupted load, use a versioned projection directory and atomic directory replacement where supported, or write a transaction marker that forces deterministic cleanup/rebuild before any section reader proceeds. Otherwise keep the current fail-closed behavior and explicitly treat the projection directory as recoverable cache rather than part of the atomic save contract.

### Regression coverage does not pin the new boundaries (**confirmed**)

The W2 diff changes Core authority, migration, terminal policy, and selection/projection behavior without adding corresponding test or self-test cases. Existing coverage exercises valid V1 migration with one known section plus a stray, ordinary checksum failures, and the happy-path projection; it does not cover the generation relabel scenario, foreign V1 identity, zero-known-section migration, quarantine followed by manifest lookup, rejected selection state, or interrupted projection cleanup. Add targeted Core and Godot-host gates before W3/W4 treats these behaviors as stable contracts.
