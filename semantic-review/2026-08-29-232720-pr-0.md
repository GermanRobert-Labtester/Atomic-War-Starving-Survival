# Expanded-shelter lifecycle ownership and reset boundary

W4 replaces three stale lifecycle labels with canonical save keys, adds lifecycle-only grouping metadata for the expanded-shelter batch, and separates in-memory reset from explicit global-save cleanup. The registry helpers preserve canonical envelope keys while exposing existing grouped sections without adding an `expanded_shelter` campaign section. Two ownership paths violate the new boundary: **confirmed** `weight_of_choices` is grouped but its faction coordinator survives reset, and **confirmed** `shelter_assignment` is grouped but still writes a projection directly instead of entering the campaign payload map. **Watch for:** **confirmed** stale `weight_of_choices` state crossing `StartNewGame`, and **confirmed** required `shelter_assignment` projection/envelope divergence; the in-memory reset’s file-safety boundary is explicit. **Verdict**: NEEDS_CHANGES

## High-level view

The alias and dependency changes are coherent: `crossing`, `expeditions`, and `caravans` resolve to `expansion_hub`, `expedition`, and `caravan`; all expanded-batch dependencies are registered; and reverse-topological reset places `expanded_shelter_batch` before `survivors`, `inventory`, and `world_weather`. The group remains lifecycle metadata derived from existing registry entries rather than a campaign section.

The reset boundary is persistence-free: `ResetAllSessionsInMemory()` clears only the in-memory capture map/flags and invokes callbacks, while the only lifecycle cleanup that deletes files is the separately invoked `DeleteGlobalSavesOnDisk()` path. **Confirmed** ownership gaps remain: one grouped owner is omitted from reset, and one grouped section bypasses aggregate capture.

3. **No W4 regression gate for the new ownership contract (confirmed)** — the existing lifecycle and registry tests do not assert alias normalization, group membership/exclusion from `All`/`SectionFileNames`, reset-side filesystem invariants, or complete grouped capture/reset coverage; add those gates before relying on the metadata as an authority.

### `weight_of_choices` is declared in the group but not reset (**confirmed**)

`SaveSectionRegistry.All` assigns `LifecycleGroup: ExpandedShelterLifecycleGroup` to `weight_of_choices`, so `SectionKeysForLifecycleGroup()` includes it in the grouped participant’s `OwnedSaveSectionKeys` through `DelegateSessionParticipant` (`Assets/Ashfall.Core/Save/SaveSectionRegistry.cs`, `Assets/Ashfall.Core/Lifecycle/SessionLifecycleRegistry.cs`, and `src/Main.Lifecycle.cs`). `SaveAllExpandedShelterSystems()` also invokes `SaveFactionBranch()` (`src/Main.ExpandedShelterSystems.cs`).

`ResetExpandedShelterSessions()` disposes/nulls the expanded host sessions and `_shelterAssignment`, but not `_factionBranch`, and it does not clear `_factionBranchDirty` (`src/Main.ExpandedShelterSystems.cs:ResetExpandedShelterSessions`). `SetupFactionBranch()` returns when `_factionBranch` is non-null (`src/Main.FactionBranch.cs:SetupFactionBranch`), so `StartNewGame()`’s `ResetAllSessions()` → `ComposeCampaign()` sequence reuses the prior coordinator instead of constructing/loading a clean one (`src/Main.GameFlow.cs:StartNewGame`, `src/Main.CampaignServices.cs:ComposeCampaign`). A later `SaveFactionBranch()` can put that prior campaign’s state into the new campaign payload map. Reset the owner within the group or register it separately with matching dependency and save ownership.

### `shelter_assignment` is grouped but still writes outside the aggregate (**confirmed**)

W4 marks `shelter_assignment` with `LifecycleGroup: ExpandedShelterLifecycleGroup`, and `SaveAllExpandedShelterSystems()` invokes `SaveShelterAssignment()` (`Assets/Ashfall.Core/Save/SaveSectionRegistry.cs`, `src/Main.ExpandedShelterSystems.cs`). `src/Main.ShelterBatch3.cs:SaveShelterAssignment` calls only `_shelterAssignment?.Save()`. `ShelterAssignmentHostSession.Save()` calls `TrySave()`, and `ShelterAssignmentSaveStore.TrySave()` writes `shelter_assignment_save.json` through `SaveSlotRoot`; it never calls `CaptureSection()`.

No current caller captures `shelter_assignment` into `_sectionPayloads`. `Main.SaveOrchestrator.SaveAll()` passes that map to `SaveEnvelopeFromPayloads()`, and `CampaignEnvelopeBuilder.Build()` emits only keys present in the map. Because the registry default leaves `shelter_assignment` as `RequiresSetup: true`, a direct projection can exist while the required section is absent from `campaign.json`; `SaveLoadHostSession.TryProjectEnvelope()` then fails closed on the orphaned required file (`src/Host/SaveLoadHostSession.cs`). Add a no-write persisted capture path and `CaptureSection("shelter_assignment", ...)`; remove the direct per-section write from the aggregate save cycle.

### Alias, ordering, grouping, and reset-side persistence boundary

`SaveSectionRegistry` maps the three historical lifecycle labels to current keys. `DelegateSessionParticipant` canonicalizes `SaveSectionKey` and owned keys, while `FileNameFor`, `SchemaVersionFor`, `TryGetKeyForSectionName`, and `TryGetSection` canonicalize before lookup. `ExpandedShelterLifecycleGroup` is absent from `SaveSectionRegistry.All` and `SectionFileNames`; `SectionsByLifecycleGroup` is derived from the 24 existing grouped metadata entries, so the group creates neither a campaign section nor a projection filename.

`expanded_shelter_batch` depends on `survivors`, `inventory`, and `world_weather`, all registered before it. `SessionLifecycleRegistry.ResetAll()` invokes callbacks in `GetReverseTopologicalOrder()`, placing the batch ahead of each declared dependency. This does not repair the omitted faction owner or the direct shelter-assignment write, but W4 introduces no missing dependency.

The in-memory deletion boundary is supported by the call graph. `Main.ResetAllSessionsInMemory()` calls `RegisterLifecycleParticipants()`, clears `_sectionPayloads` and `_sectionCaptureFailed`, then calls `SessionLifecycleRegistry.ResetAll()`. `ResetAll()` only invokes `OnReset`; `ResetExpandedShelterSessions()` contains no `File.Delete`, `Directory.Delete`, `SaveSlotRoot`, or `user://` operation, and its host-session `Dispose()` implementations inherit `StatefulSessionBase.Dispose()`, which only clears event handlers. `DeleteGlobalSavesOnDisk()` is called by private destructive `ResetAllSessions()` after the in-memory reset, so the read-only reset cannot delete slot-root or global `user://` files.
