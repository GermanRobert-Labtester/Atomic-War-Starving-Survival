### C# placement framework — existing API anchors

The fragment identifies call direction and a real API anchor. It is not a new subsystem, a complete patch, or permission to edit a claimed composition root. Variables come from the owning method; the builder reconciles signatures against source during Phase 0.

```csharp
_regionalTreaty = new RegionalTreatyHostSession(rtSys);
rtSys.OnTreatyTransition += transition =>
    OnTreatyTransitionWorldConsequences(rtSys, transition);
// The RegionalTreatySystem state is restored before this event binding;
// restore must not emit a second standing or radio consequence.
```

**Command contract.** A command enters the current host with a stable subject ID and day. Validate the actor and authored reference before an irreversible mutation. Return the owner’s accepted result or a specific refusal. Only the owner named above changes the destination value. The host may translate a typed fact, mark its existing section dirty, and publish a read model; it must not calculate a competing rule.

**Capture contract.** The record that prevents repeat effects must live with the mutation owner or a signed transaction carrier. A process-local boolean is not persistence. A restore reconstitutes Core state, then host subscriptions, then UI bindings. If a copied scene can apply only after another section loads, describe the pending state and recovery instead of assuming all saves are atomic.

**Projection contract.** The player view shows a label, source, day, current consequence, available command, and refusal from the owner. It may format values and choose restrained diegetic wording, but cannot infer a hidden diagnosis, species count, item property, potable-water status, treaty standing, or completed treatment from incomplete evidence. The panel's read path should be safe to call repeatedly and after save/load.

**Focused proof specimen.** A small test or host probe should start from one real catalog row and one producer fact, assert the authoritative destination field before and after, capture and restore state, replay the same ID, and assert no duplicate effect. Another input should be invalid at the exact boundary this plan touches. When UI is in scope, verify read-only refresh, visible refusal, and focus return; a build-only result is structural evidence rather than runtime reachability.

### Command boundary

A player action enters through its current Main/host route with canonical actor ID, target ID, campaign day, source event ID and catalog reference. Validate the actor and referenced content before calling the named Core owner. Return an existing ActionResult shape where one is available; otherwise propose a typed accepted/blocked result in the current host rather than passing a raw boolean to a button. The result names the committed source ID and a stable blocker key. This framework is a proposal for the implementing integrator, not a claim that the methods below already exist.

```csharp
// Proposed command context. Check current ActionResult conventions first.
public sealed class IntegrationCommandContext
{
    public string ActorId { get; init; } = string.Empty;
    public string TargetId { get; init; } = string.Empty;
    public string SourceEventId { get; init; } = string.Empty;
    public int CampaignDay { get; init; }
}
```

### Save and lifecycle order

No FactionDiplomacySystem production host save section was observed. Bilateral treaty state needs a named section decision before activation; regional_treaty and summit records remain under their current owners. Validate the catalog, create or select the one owning Core instance, restore that section, then bind event adapters and UI. Capture after an accepted command and before dirty flags are cleared. When two existing sections change in one journey, document capture order and the recovery behavior for a save between them. Restore must not replay a player reward, resource transfer, relationship delta or notification. An old save missing the section gets the documented empty or seeded baseline, not fabricated historical actions. A future schema uses the current codec rejection rule and a corrupt envelope must not masquerade as a valid empty state.

### Deterministic day and event order

Use `_simDay` or the campaign day coordinator argument, never a literal UI day or wall-clock clock. A day tick runs once per accepted campaign day and sorts unstable source collections by stable ID before effects. A read-only projection is pure; reopening a panel cannot fire a Core command. For each subscription, name where it is bound, when it is unbound, and whether restore can emit it. If the source event is retried, an owner-persisted key or already-committed state prevents the second effect; a process-local flag is insufficient.

### Player surface and accessibility

Show current state, legal action, cost and consequence, and precise blocker in the same view. Preserve keyboard/controller back and focus after an action or refresh. Display long authored text with wrapping and scroll, preserve empty states, and keep private/undiscovered content gated. A card never shows a morale, skill, resource, room or map outcome unless the matching authority has committed it. Bounded visible rows may paginate without truncating saved records.

### Reviewable phases and rollback

Phase 0 records current source/data/host evidence and an exact path claim. Phase 1 seals the owning Core command and one refusal. Phase 2 validates catalog IDs and references. Phase 3 wires save and day through current ownership. Phase 4 exposes one player route. Phase 5 adds authored content only after that route can consume it. Focused tests are selected under TEST_POLICY.md when implementation begins. A failed phase can be reverted without discarding other owner state; incomplete effects are reported as blocked, not quietly simulated in UI.
