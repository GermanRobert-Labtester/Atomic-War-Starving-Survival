## 1. Objective and bounded outcome

Make the investigation and confrontation path truthful: gate private details until discovery, source actual investigator skill and campaign day, guard one investigation/day and duplicate tick, and route one accepted resolution consequence to its canonical owner. Expand clue text only when it can be discovered through this route.

**Current state:** DEC-117 signed six archetypes and Core consequence delegates. Main restores hidden_agenda, loads the catalog, seeds a SecretProtection agenda for the first roster survivor on an empty state, ticks daily, captures state and opens HiddenAgendaPanel. The panel currently lists all agendas, including [SECRET] rows with type, target, notes and progress, and passes investigatorSkill=25f and day=1 to Investigate; Confront uses the host default day=1. Core TickDay raises passive progress after ten days without a last-ticked-day guard. The src sweep found no production binding of the three consequence applier delegates.

**Non-goals:** No omniscient secret dossier, free repeated investigations, fixed day-one evidence, fake confiscated stock, standing or morale applied in a panel, or new betrayal authority alongside HiddenAgendaSystem.

**First deliverable:** one vertical slice with a real producer fact, one canonical destination owner, save/reload parity, and a truthful player readout. Later slices are separate claims and must repeat the premise check.

### Disclosure and consequence dossier

The hidden-agenda system is live, but its panel currently reveals the secret it is supposed to let the player investigate. It labels an agenda `[SECRET]` and still displays type, target faction, target survivor, notes and exact discovery progress in both list and detail view. The first UI slice needs a disclosure-filtered host projection, not a label-level hide that leaves raw DTOs accessible to the panel. Before discovery the player may see a suspicion cue and legitimately found clues; only after the threshold should the agenda category and target appear. Clue text must be tied to a real investigation or passive discovery fact and avoid revealing a future resolution. The already-seeded agenda should be evaluated for intended narrative and faction validity on a new campaign.

The investigation button passes hardcoded skill 25 and day 1. Core accepts these values and creates a new clue/progress each call, so repeated clicks can reveal an agenda without time or resource cost. A Main or host command should validate a current investigator, skill, opportunity and campaign day, then record an attempt key or day limit in the existing agenda state. Confrontation must receive the real day and should remain unavailable until evidence reaches Core's 60% threshold. Core's passive daily progress also needs duplicate-day protection before a resumed or repeated tick can add multiple points.

Resolution delegates are optional and currently unbound in the inspected src tree. A reconciliation result should call Needs once; faction fallout should use the standing authority; confiscation must transfer an item actually present through Inventory. The Core method currently marks an agenda resolved before invoking these delegates, so an absent or rejecting destination must produce a documented pending/blocked contract. Expulsion or betrayal must not delete a survivor from the roster merely because the enum says so. Expand six archetypes with distinct clues only after this disclosure and consequence route is sealed.


Before code edits, inspect existing equivalent producers and consumers with `rg`, read their public methods and save snapshots, and write a one-page premise note. If another live owner already mutates the target concern, use it. If a required write API does not exist, return the proposed consumer hook to the foreman as an authority decision. Do not create a side ledger to bypass that missing API.

## 8. Event, day and failure semantics

One semantic fact should carry stable source ID, campaign day, owning entity ID, content ID if any, and enough context for the destination owner to decide. The host may route the fact but may not calculate a competing gameplay rule. Define when the fact is emitted, when a command is committed, and what is durable before the next callback. A read-only query must not create journal entries or rewards on every panel refresh.

Use the canonical day owner only for behavior that genuinely changes with time. Preserve the current day phase ordering and forked seeded RNG contract. No wall-clock seed, hash-order iteration, or System.Random belongs in deterministic Core. Replay after load must not repeat a completed effect; an effect that was not committed must remain recoverable. When a destination owner rejects a command, keep the source fact and show a reason rather than writing a partial substitute effect.
