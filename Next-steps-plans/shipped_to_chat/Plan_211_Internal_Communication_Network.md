### Deterministic day and event protocol

Use the campaign day provided by the current coordinator. A day callback is bound once to the session lifetime and receives one integer day. Cache no wall-clock dates. For each event subscription, list its registration method, owner, unsubscription/disposal path, and whether restoring an owner emits the event. ### Player surface protocol

The first screen presents current state, available action, cost or prerequisite, consequence, and specific blocker. It calls one host command and then refreshes from the owner read model. Its open, close, reload and survivor/room selection path must preserve focus and keyboard/controller back. Do not add an unbound button, a fake preview value, or a tooltip claiming a result that no owner applies. Check empty, one-row and many-row views and bound the number of visible rows without deleting saved records.

### Dependency gate and rollback

The integrator claims exact files in WORKTREE_OWNERSHIP.md, records a current premise note, and resolves any authority decision before implementation. Phase 1 commits owner-safe API and refusal; Phase 2 commits catalog load and validation; Phase 3 commits save and day wiring; Phase 4 commits UI.
