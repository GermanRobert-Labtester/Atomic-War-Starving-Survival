## 1. Objective and bounded outcome

Trace one saved phase or season transition into one current heating, expedition or greenhouse owner using its accepted modifier seam, then show the observed climate and reason in the existing weather surface. Preserve the phase journal and add anomaly prose only with a real anomaly event and consumer.

**Current state:** DEC-159 signed five phases and four seasons. ORPHAN-SEAL-W1 loads the catalog, restores nuclear_winter_progression, calls AdvanceDay with a campaign Weather RNG fork, captures state, and journals phase changes. The host exposes CalculateHeatingDemand, CalculateExpeditionRisk and CalculateCropYieldMultiplier, but this src sweep found no production consumers of those three methods. Core also has phase, season and anomaly seams that need consumer checks before player consequence claims.

**Non-goals:** No parallel weather clock, extra fuel debit from a weather panel, duplicate radiation dose, three independent winter multipliers applied to the same crop, arbitrary wall-clock seasons, or claimed decades of simulation from a short test fixture.

**First deliverable:** one vertical slice with a real producer fact, one canonical destination owner, save/reload parity, and a truthful player readout. Later slices are separate claims and must repeat the premise check.

### Climate ownership and effect-route dossier

The winter system is live as a day-updated climate state and a phase journal. It is not yet proof of increased fuel use, altered expedition risk or greenhouse protection. The three calculator methods appear only in Core and their host wrapper in the src sweep. The first slice should choose one destination, read its existing modifier inputs, and apply a single climate fact through that owner. Heating is a good candidate if the current boiler/fuel consumer exposes a demand modifier. If no appropriate input exists, request that specific seam rather than deducting fuel in Main. Each effect needs a source day, phase/season ID and one accepted consumer result.

`EvaluateClimate` mixes phase and season definitions with seeded jitter when supplied. `AdvanceDay` records transitions and can emit severe anomaly facts. A saved phase transition must not be replayed as a second journal entry on restore; a day repeat must not consume a second jitter roll or anomaly effect. Phase definitions span long ranges, so fixtures should test exact boundaries and selected sampled days rather than simulate every year. Catalog validation should reject gaps/overlaps, unbounded multipliers, missing season duration and unknown IDs with direct row diagnostics. The existing fallback catalog is a safety behavior, not permission to hide an invalid authored catalog.

The player weather view can explain current phase, seasonal daylight, temperature range and confidence without claiming ownership of a specific room temperature. A severe anomaly can provide an authored notice only if a Core anomaly event has an ID and the weather, expedition or shelter effect is committed. Winter prose should be local and restrained; it may evoke ash light or cold corridors, but it cannot assert failed crops or illness without those owners reporting it.


Before code edits, inspect existing equivalent producers and consumers with `rg`, read their public methods and save snapshots, and write a one-page premise note. If another live owner already mutates the target concern, use it. If a required write API does not exist, return the proposed consumer hook to the foreman as an authority decision. Do not create a side ledger to bypass that missing API.

## 8. Event, day and failure semantics

One semantic fact should carry stable source ID, campaign day, owning entity ID, content ID if any, and enough context for the destination owner to decide. The host may route the fact but may not calculate a competing gameplay rule. Define when the fact is emitted, when a command is committed, and what is durable before the next callback. A read-only query must not create journal entries or rewards on every panel refresh.

Use the canonical day owner only for behavior that genuinely changes with time. Preserve the current day phase ordering and forked seeded RNG contract. No wall-clock seed, hash-order iteration, or System.Random belongs in deterministic Core. Replay after load must not repeat a completed effect; an effect that was not committed must remain recoverable. When a destination owner rejects a command, keep the source fact and show a reason rather than writing a partial substitute effect.
