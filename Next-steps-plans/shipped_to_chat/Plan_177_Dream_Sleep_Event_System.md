## 1. Objective and bounded outcome

Identify one real completed sleep transition and its current rest/psychology owners, then add a bounded dream record and lawful private readout only if the new DreamSystem state earns a distinct host/save owner. Apply any numeric rest, trauma or morale result through existing authorities once after a signed composition rule.

**Current state:** DreamSystem and dream_templates.json are present in Core/data, with ProcessSleepCycle and interpretation state. The inspected src tree had no DreamSystem construction or ProcessSleepCycle production call. Main.SleepNarrative already reads SurvivorMentalHealthRecord and writes a bounded, deduplicated journal beat; its own comment expressly says no DreamSystem. The prior DEBT-177 sleep narrative seal is complete and must not be reopened as a substitute dream ledger.

**Non-goals:** No supernatural prophecy presented as fact, duplicate nightly mental-health tick, direct needs mutation from dream prose, journal spam, dream generation for dead/awake survivors, or second trauma ledger.

**First deliverable:** one vertical slice with a real producer fact, one canonical destination owner, save/reload parity, and a truthful player readout. Later slices are separate claims and must repeat the premise check.

### The night boundary and private interpretation

The DreamSystem can generate a record, rest bonus, trauma delta and morale delta. Those are potential consequences, not proof of integration. The host currently has a separate read-only sleep narrative beat that classifies stress, crisis and insomnia and writes only a bounded journal line. A future dream lifecycle must start from a real sleep transition, not the generic daily psychology tick, or it will record dreams for survivors who did not sleep. Confirm one sleep event, one campaign day, one survivor and one seeded RNG fork. If the current simulation cannot identify completed sleep, this plan should stay at a bounded integration dependency rather than treating every day as a night.

Dream content should be private and nonomniscient. Memory fragments can be misremembered; anxiety can distort detail; “prophetic” labels in the catalog are creative classification, not confirmation of supernatural facts or future world events. Interpretation is a survivor/player choice with an explicit audience and no automatic revelation of hidden agendas. The panel may show a record only for a lawful view and should not leak another survivor's private journal in an alert or public roster summary.

Numeric effects need a composition decision. The needs owner already determines rest. Mental-health and morale have current owners. A dream result can request bounded deltas once, with source record ID and applied status durable across save/reload; it cannot directly overwrite those systems. If that contract is not approved, ship dream records as presentation-only and make the absence of mechanical effects explicit. The existing SleepNarrativeProjection continues as a distinct lightweight signal and its dedup remains intact.


Before code edits, inspect existing equivalent producers and consumers with `rg`, read their public methods and save snapshots, and write a one-page premise note. If another live owner already mutates the target concern, use it. If a required write API does not exist, return the proposed consumer hook to the foreman as an authority decision. Do not create a side ledger to bypass that missing API.

## 8. Event, day and failure semantics

One semantic fact should carry stable source ID, campaign day, owning entity ID, content ID if any, and enough context for the destination owner to decide. The host may route the fact but may not calculate a competing gameplay rule. Define when the fact is emitted, when a command is committed, and what is durable before the next callback. A read-only query must not create journal entries or rewards on every panel refresh.

Use the canonical day owner only for behavior that genuinely changes with time. Preserve the current day phase ordering and forked seeded RNG contract. No wall-clock seed, hash-order iteration, or System.Random belongs in deterministic Core. Replay after load must not repeat a completed effect; an effect that was not committed must remain recoverable. When a destination owner rejects a command, keep the source fact and show a reason rather than writing a partial substitute effect.
