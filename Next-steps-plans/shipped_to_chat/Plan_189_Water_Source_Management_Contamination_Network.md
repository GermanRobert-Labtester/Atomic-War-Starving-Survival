# Plan 189 — Water Sources and Contamination — Measured Intakes, One Treatment Path, and Honest Switching

> Integration plan revision: 2026-09-24. Source of truth: current repository source and data, then AGENTS.md, then [docs/newest-ashfall-master-expansion-authority-v2-0-complete-compiled-edition-volumes-1-57.md](../../docs/newest-ashfall-master-expansion-authority-v2-0-complete-compiled-edition-volumes-1-57.md). This document is a planning artifact. It does not claim paths or authorize a competing implementation package.

## 1. Objective and bounded outcome

Bind one real discovered source to one verified intake/treatment command with measured contamination and volume, then persist the source selection under a signed owner and show a truthful panel readout. Expand to connected network propagation only where current geography/weather facts and treatment consumers exist.

**Current state:** WaterSourceSystem and water_sources.json exist with definitions, connections, discovery, active source, day tick, water testing and maintenance. The inspected src tree had no production WaterSourceSystem construction or calls; current WaterTreatmentHostSession and WaterTreatmentPanel own the live purification surface and water_treatment save. WaterQualityProfileEngine and regional water owners also exist, so source-water identity must be traced before any network or switch can change drinking stock.

**Non-goals:** No parallel clean-water inventory, instant source switch without pipe/route, contamination guessed from lore, test result without kit/worker cost, or source-only state that bypasses treatment.

**First deliverable:** one vertical slice with a real producer fact, one canonical destination owner, save/reload parity, and a truthful player readout. Later slices are separate claims and must repeat the premise check.

## 3. Current contract and collision firewall

- **Evidence or explicit premise:** WaterSourceSystem and water_sources.json provide source definitions, connections, tests and save state.
- **Evidence or explicit premise:** No production src WaterSourceSystem construction or water_sources save section was found.
- **Evidence or explicit premise:** water_treatment is already registered and has a host session and panel.
- **Evidence or explicit premise:** WaterQualityProfileEngine supplies another water-quality concern requiring a collision audit.
- **Evidence or explicit premise:** A discovered source or active ID alone is not a physical intake route into treatment.
- **Evidence or explicit premise:** Testing and maintenance require worker, kit, cost and current day ownership decisions.

### A source record is not a pipe full of drinking water

WaterSourceSystem can track wells, rain collection or other sources, switch an active source, test it and calculate available water. The production host currently does not construct it. The live treatment system already owns purification, and inventory/needs own clean water and consumption. The first integration slice should name an actual intake connection from source to treatment, the measured raw volume and contamination, and the treatment owner's accepted processing command. `SetActiveSource` should select a candidate input only after that route exists; otherwise the UI must label it a planning choice, not a flowing pipe.

Testing must be an action with a kit or laboratory resource, a worker and a day. An authored contamination value can initialize a source profile, but a current reading is only known after the test owner records it. A test can be stale, wrong within known accuracy bounds, or invalidated by a weather event. The panel should distinguish modeled risk, last measured result and treated output. A water warning must not claim that the whole shelter has drunk contaminated water unless inventory/needs consumption and exposure owners confirm that path.

Network connections in the JSON catalog should be validated against source and room IDs. A contamination spike may travel through an actual connection after a documented delay, but should not jump between unrelated sources. Old saves with only water_treatment remain valid; if a water_sources section is approved, it begins from a safe source baseline without retroactively inventing tests or illness.


Before code edits, inspect existing equivalent producers and consumers with `rg`, read their public methods and save snapshots, and write a one-page premise note. If another live owner already mutates the target concern, use it. If a required write API does not exist, return the proposed consumer hook to the foreman as an authority decision. Do not create a side ledger to bypass that missing API.

## 8. Event, day and failure semantics

One semantic fact should carry stable source ID, campaign day, owning entity ID, content ID if any, and enough context for the destination owner to decide. The host may route the fact but may not calculate a competing gameplay rule. Define when the fact is emitted, when a command is committed, and what is durable before the next callback. A read-only query must not create journal entries or rewards on every panel refresh.

Use the canonical day owner only for behavior that genuinely changes with time. Preserve the current day phase ordering and forked seeded RNG contract. No wall-clock seed, hash-order iteration, or System.Random belongs in deterministic Core. Replay after load must not repeat a completed effect; an effect that was not committed must remain recoverable. When a destination owner rejects a command, keep the source fact and show a reason rather than writing a partial substitute effect.
