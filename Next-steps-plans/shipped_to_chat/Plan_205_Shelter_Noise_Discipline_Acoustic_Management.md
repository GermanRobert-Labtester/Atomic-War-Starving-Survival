## 1. Objective and bounded outcome

Replace static baseline source assumptions with current machinery/activity facts where available, prove one quiet-hours violation and one room soundproofing effect, then route a bounded detection-risk fact to the actual defense/stealth owner if it has an accepted seam. Show room and shelter noise as observations with readable cues.

**Current state:** Plan 205 is live with Plan 220. Main loads 15 noise-source definitions, restores shelter_noise, seeds baseline generator/ventilation/workshop sources when empty, and updates atmosphere daily. ShelterAtmosphereHostSession ticks ShelterNoiseSystem at hour 12, derives acoustic comfort and exposes quiet hours/soundproofing commands. Core computes room and overall noise plus DetectionRisk and emits spike/risk events. The source sweep found no production defense or stealth consumer of DetectionRisk; prose must distinguish measured noise from an actual discovered threat.

**Non-goals:** No second sound engine, free soundproofing from a panel button, threat spawned from descriptive noise alone, duplicate morale already applied by atmosphere, or every source represented as permanently active.

**First deliverable:** one vertical slice with a real producer fact, one canonical destination owner, save/reload parity, and a truthful player readout. Later slices are separate claims and must repeat the premise check.

### Acoustic source, risk and sensory dossier

ShelterNoiseSystem is not an orphan. Its state is composed with the atmosphere host, saved in `shelter_noise`, and sampled daily at midday. The major precision gap is source provenance. Main currently seeds generator, ventilation and workshop noise when the state has no sources; a generator may later be off, damaged or physically relocated, while a workshop may be idle. The first slice should bind one real PowerGrid or work activity fact to source active state and room ID, then compare the room reading before/after. Catalog definitions describe possible sounds, not proof the source is running. If the source owner cannot report activity, present it as baseline assumption and avoid claiming measured operation.

Quiet hours are a Core setting. A violation is calculated when `TickDay` samples an hour in the configured period and the overall level exceeds the threshold; the current host calls at hour 12. With the default 22–06 window, a midday tick cannot observe night noise. The implementing package needs a real hour callback or a documented daily aggregate of overnight activity. It must not fake a night violation by passing 23 while only daytime conditions are known. A second same-hour call should not append a second event. Soundproofing should require an accepted project/material transaction and a built room; the Core command alone is not construction.

DetectionRisk increases with high noise and decays otherwise, but no production defense/stealth consumer was found. A bridge should send one bounded acoustic exposure fact to the current threat owner if its API accepts such inputs. Do not spawn an attacker or reveal a hidden threat from a risk score alone. Godot audio cues and UI descriptions should map to observed sources and respect volume/accessibility settings; a player with audio muted still needs text such as an equipment vibration or ventilation hum. Additional flavor should vary by room, activity and hour, not repeat a generic claim that the shelter is noisy.


Before code edits, inspect existing equivalent producers and consumers with `rg`, read their public methods and save snapshots, and write a one-page premise note. If another live owner already mutates the target concern, use it. If a required write API does not exist, return the proposed consumer hook to the foreman as an authority decision. Do not create a side ledger to bypass that missing API.

## 8. Event, day and failure semantics

One semantic fact should carry stable source ID, campaign day, owning entity ID, content ID if any, and enough context for the destination owner to decide. The host may route the fact but may not calculate a competing gameplay rule. Define when the fact is emitted, when a command is committed, and what is durable before the next callback. A read-only query must not create journal entries or rewards on every panel refresh.

Use the canonical day owner only for behavior that genuinely changes with time. Preserve the current day phase ordering and forked seeded RNG contract. No wall-clock seed, hash-order iteration, or System.Random belongs in deterministic Core. Replay after load must not repeat a completed effect; an effect that was not committed must remain recoverable. When a destination owner rejects a command, keep the source fact and show a reason rather than writing a partial substitute effect.
