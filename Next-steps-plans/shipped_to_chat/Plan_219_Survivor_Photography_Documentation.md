### Save transaction and restore protocol

Record the exact current save DTO and codec field names. For each accepted command, write an acceptance trace containing the owner state before mutation, the command ID, the owner state after mutation, and the existing aggregate section that captures it. If two sections change, document capture order and recovery for a save between the writes. Restore validated catalogs first, then the aggregate state, then attach event listeners, then bind UI. Never fire historical command events while restoring. An old save missing the new field gets an empty/default state with monotonic next IDs. A corrupt checksum follows the existing store refusal path; do not ignore the failure and fabricate an empty success.

### Deterministic day and event protocol

Use the campaign day provided by the current coordinator. A day callback is bound once to the session lifetime and receives one integer day. Cache no wall-clock dates. Sort any dictionary-derived output by stable ID before serialization or view projection. For each event subscription, list its registration method, owner, unsubscription/disposal path, and whether restoring an owner emits the event. If the owner emits during restore, defer subscriptions until after restore or add a documented restore guard in the current host.

### Player surface protocol

The first screen presents current state, available action, cost or prerequisite, consequence, and specific blocker. It calls one host command and then refreshes from the owner read model. Its open, close, reload and survivor/room selection path must preserve focus and keyboard/controller back. Do not add an unbound button, a fake preview value, or a tooltip claiming a result that no owner applies. Check empty, one-row and many-row views and bound the number of visible rows without deleting saved records.

### Dependency gate and rollback

The integrator claims exact files in WORKTREE_OWNERSHIP.md, records a current premise note, and resolves any authority decision before implementation. Phase 1 commits owner-safe API and refusal; Phase 2 commits catalog load and validation; Phase 3 commits save and day wiring; Phase 4 commits UI.
