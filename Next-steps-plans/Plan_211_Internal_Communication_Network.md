## 3. Current contract and collision firewall

- **Evidence or explicit premise:** InternalCommunicationSystem exposes PostMessage, PostFromTemplate, BroadcastIntercom, AcknowledgeIntercom, MarkAsRead, AcknowledgeMessage, recipient/public queries, AddBulletinBoard, TickDay, CaptureState and RestoreState.

- **Evidence or explicit premise:** MarkAsRead and AcknowledgeMessage locate a message by ID but do not visibly authenticate the reader or acknowledger. Private mail must be guarded before a player route can expose those commands.
- **Evidence or explicit premise:** The registered `communications` save section belongs to radio/antenna communication; name similarity does not confer internal-network ownership.
- **Evidence or explicit premise:** At premise time the source sweep found no `src` construction of InternalCommunicationSystem. The completed implementation now records the single host instance, dedicated save custody, and existing-route projection without changing the external radio owner.

### Internal network custody dossier

The signed Core authority is already valuable: a message state, board state, intercom acknowledgement list, stable `msg_`, `ann_`, and `board_` identities, and deterministic expiry by campaign day. The old draft's instruction to create these classes is delivered. The missing work is a truthful host binding with a single lifetime, validated catalog load, a campaign day callback, an exact save owner, and a player route. A proposal to embed this state in a shelter or social aggregate must document why that aggregate owns the lifecycle; the integrator must approve the chosen section and registration before code is touched.

The first vertical slice should post the existing water advisory template from a real rationing fact and show it on one shelter board. For private mail, enforce sender/recipient identity and read permissions in the command owner before binding UI.

The seven JSON templates are content definitions. They do not establish a bulletin route, delivery service or room capacity by themselves. Validate IDs, category and duration against Core parsing before host activation. If a template is absent on an old save, preserve saved messages and display their stored subject/content without inventing a new template row.


Before code edits, inspect existing equivalent producers and consumers with `rg`, read their public methods and save snapshots, and write a one-page premise note. ## 8. Event, day and failure semantics

One semantic fact should carry stable source ID, campaign day, owning entity ID, content ID if any, and enough context for the destination owner to decide. The host may route the fact but may not calculate a competing gameplay rule. Define when the fact is emitted, when a command is committed, and what is durable before the next callback. A read-only query must not create journal entries or rewards on every panel refresh.
Use the canonical day owner only for behavior that genuinely changes with time. Preserve the current day phase ordering and forked seeded RNG contract. No wall-clock seed, hash-order iteration, or System.Random belongs in deterministic Core. Replay after load must not repeat a completed effect; an effect that was not committed must remain recoverable. When a destination owner rejects a command, keep the source fact and show a reason rather than writing a partial substitute effect.
