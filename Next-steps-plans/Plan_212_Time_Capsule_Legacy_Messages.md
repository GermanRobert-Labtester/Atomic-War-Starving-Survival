> Integration plan revision: 2026-09-24. Source of truth: current repository source and data, then AGENTS.md, then [docs/newest-ashfall-master-expansion-authority-v2-0-complete-compiled-edition-volumes-1-57.md](../../docs/newest-ashfall-master-expansion-authority-v2-0-complete-compiled-edition-volumes-1-57.md). ## 1. Objective and bounded outcome

Seal the existing capsule route so opening uses the campaign day and lawful condition, pending letters remain private, and one delivered message or opened capsule produces a bounded observable outcome. Then add only authored capsules/notes whose source and delivery path are real.

**Current state:** DEC-115 signed four preplaced capsules, Core sentimental and bereavement calculations, and existing host/day/save/panel. Main.TimeCapsule loads the catalog, TickTimeCapsule runs from ExpandedShelterSystems, and one real defense event calls NotifyTimeCapsuleEvent. TimeCapsulePanel currently calls OpenCapsule with literal opener Overseer and day 1 and renders pending legacy-message content; Core OpenCapsule itself does not check its opening condition.

**Non-goals:** No second legacy-message store, auto-granted inventory artifact, UI bypass of date/event conditions, bereavement boost on every refresh, disclosure of undelivered letters, or generated survivor identity.

**First deliverable:** one vertical slice with a real producer fact, one canonical destination owner, save/reload parity, and a truthful player readout. Later slices are separate claims and must repeat the premise check.

## 3. Current contract and collision firewall

- **Evidence or explicit premise:** TimeCapsuleSystem owns CreateCapsule, OpenCapsule, TryOpenEventCapsules, WriteMessage, TickDay, DeliverDeathMessages, LoadCatalog, GetOpenedCapsuleMoraleBonus, CalculateBereavementComfort and CaptureState/RestoreState.
- **Evidence or explicit premise:** OpenCapsule only checks existence and IsOpen; it does not itself gate DateBased, EventBased, or SurvivorBased conditions. The current TimeCapsulePanel button passes "Overseer" and day 1 for every sealed capsule, bypassing a truthful condition route.
- **Evidence or explicit premise:** TimeCapsulePanel renders every LegacyMessage.Content while status may still be PENDING. A private message projection must filter or redact until legitimate delivery and recipient visibility.
- **Evidence or explicit premise:** Main.TimeCapsule loads time_capsules.json, constructs the host, persists time_capsules, and TickTimeCapsule is called from the expanded shelter day path.
- **Evidence or explicit premise:** NotifyTimeCapsuleEvent is called for defense_assault_repelled; new event capsule content needs a real producer rather than a placeholder trigger.
- **Evidence or explicit premise:** GetOpenedCapsuleMoraleBonus and CalculateBereavementComfort are calculations, not proof that NeedsSystem has applied an effect.

### Existing custody and disclosure analysis

The signed system is already integrated on the host path. The residual is correctness of access and presentation. `OpenCapsule` is permissive; `TickDay` enforces DateBased timing only when it chooses to call OpenCapsule, and `TryOpenEventCapsules` matches an event ID before calling it. The panel bypasses both with a direct button, a literal opener and day 1. The first implementation slice should move the command to Main or a session method that reads `_simDay`, validates author and condition, and reports an explicit blocked reason. The Core owner should enforce the invariant if other callers may invoke OpenCapsule. One source event must open at most once; save/reload must preserve IsOpen and OpenedDay without replaying morale.

The panel currently shows pending message bodies. Legacy messages can carry bereavement letters and private survivor text; a public overview may show sender, recipient, delivery condition and pending count but not content until the message is delivered to an authorized viewer. The read model should be defined at host level and supplied to the panel. Do not rely on the panel hiding a label while raw DTOs remain available through a generic bind. `IsRead` exists but no read command appeared in this sweep, so an unread badge may be displayed only if a real acknowledgement route is defined.

Four authored capsules are present. New found notes or bereavement letters require an origin, delivery predicate, lawful audience, and catalog reference validation. Content with item_id should be descriptive until Inventory has a signed transfer; opening a vault does not mint `item_antique_theodolite` or other physical stock. `CalculateBereavementComfort` may inform a one-time attributed Needs delta only after actual delivery. SurvivorDeathLegacySystem already has a bereavement rule, so the bridge must prove it adds a distinct event and does not double comfort.


Before code edits, inspect existing equivalent producers and consumers with `rg`, read their public methods and save snapshots, and write a one-page premise note. If another live owner already mutates the target concern, use it. If a required write API does not exist, return the proposed consumer hook to the foreman as an authority decision. Do not create a side ledger to bypass that missing API.

## 7. State, save and migration

Inspect `src/Host/TimeCapsuleSaveStore.cs` and the registry for the named concern; absence of a section is a decision gate, not permission to invent one. Write down exact DTO version, constructor baseline, capture point, restore point, and dirty flag. For a stateless bridge, persist only the source and destination authorities; do not create a bridge section. If a new mutable field is genuinely required, version the existing owner DTO and prove migration from the preceding schema. Never equate a panel cache with campaign state.
The restore sequence is: catalog validated; source state restored; destination state restored; adapters bound; pending effects reconciled once; UI bound; day processing resumes. A new campaign starts with an explicit empty/default state. A legacy save without the field takes that same baseline without inventing past events. Unknown future schema versions must fail or degrade according to the existing save contract, with a visible diagnostic. Corrupt single records must not silently reset an entire unrelated section.

## 8. Event, day and failure semantics

One semantic fact should carry stable source ID, campaign day, owning entity ID, content ID if any, and enough context for the destination owner to decide. The host may route the fact but may not calculate a competing gameplay rule. Define when the fact is emitted, when a command is committed, and what is durable before the next callback. A read-only query must not create journal entries or rewards on every panel refresh.
Use the canonical day owner only for behavior that genuinely changes with time. Preserve the current day phase ordering and forked seeded RNG contract. No wall-clock seed, hash-order iteration, or System.Random belongs in deterministic Core. Replay after load must not repeat a completed effect; an effect that was not committed must remain recoverable. When a destination owner rejects a command, keep the source fact and show a reason rather than writing a partial substitute effect.

## 9. Player commands and UI

Inspect the current route to `src/UI/TimeCapsulePanel.cs` and its bind/open/close methods. Expose only commands backed by an existing Core method or a specifically planned method in the named owner. The panel should show source state, currently legal action, expected cost, blocker, committed outcome, and uncertainty where the game cannot know more. Refresh on authoritative state change and after restore; unbind subscriptions on close/disposal. Preserve keyboard/controller back and readable contrast.
