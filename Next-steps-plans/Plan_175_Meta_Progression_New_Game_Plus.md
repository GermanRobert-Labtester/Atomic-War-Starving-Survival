# Plan 175 — Meta Progression & New Game+ Orchestration — Cross-Run Profile Persistence, Prestige Currency Valuation, Unlockable Boons, and New Game+ Bootstrap

## 1. Objective and bounded outcome
Deliver the canonical, authoritative implementation and integration architecture for **Plan 175 (Meta Progression & New Game+ Orchestration)**. This specification establishes the immutable system contracts, host wiring, data schemas, persistence boundaries, deterministic day semantics, failure handling, UI adapters, and verification protocols required to operate within the ASHFALL runtime without introducing parallel authority, architectural fragmentation, or save corruption.
**Current production state:** The system is governed by `DEC-167 (signed 2026-09-21), DEC-315 (signed 2026-09-24)` and anchored in Master Expansion Authority `Volumes 1-57 Master Expansion Authority (Part III C13 Endgame/Epilogue, C16 Meta-Progression, v1.0 Part 6.6 Epilogue Permutations)` under subsystem cluster `C13 Endgame and epilogue / C16 Progression and meta / C10 Quests and moral choice`. Pure domain logic is anchored in `Assets/Ashfall.Core/Endgame/MetaProgressionSystem.cs`. Host composition routes through `src/Host/MetaProgressionHostSession.cs` and `src/Main.MetaProgression.cs`. Data definitions are authored strictly in `Assets/StreamingAssets/Data/meta_unlockables.json`. Persistence and profile custody adhere strictly to `CrossRunProfileStore (isolated user profile JSON outside save slots, checksum-validated; C3 HOLD residual resolved)`. Comprehensive verification is gated via `Ashfall.Core.Tests/Endgame/Plan175MetaProgressionHostIntegrationTests.cs`.
### Non-goals and strict boundaries:
1. **Zero engine leaks:** Pure Core domain logic in `Assets/Ashfall.Core/` must never reference Godot, UnityEngine, or engine serialization APIs.
2. **No parallel state stores:** Do not create auxiliary ledgers, shadow registries, or independent state stores that bypass the canonical save section or settings authority.
3. **JSON authority:** Authored configurations reside exclusively in `Assets/StreamingAssets/Data/` under validated schemas. Runtime code must not hardcode gameplay authority tables.
4. **Deterministic execution:** All calculations, timers, random rolls, and state transitions must be strictly reproducible using seeded random streams (`ISeededRng`). Wall-clock time or unseeded `System.Random` is strictly prohibited.

## 7. State, save and migration

The state envelope records schema version, timestamp/day, and immutable record lists. Migrations between schema versions must be explicit, unit-tested, and idempotent.

## 8. Event, day and failure semantics
Events represent immutable facts that have already occurred. Handlers must be idempotent; receiving an identical event multiple times must not compound mutations. Daily processing hooks into `CampaignDayCoordinator.OnDayAdvanced`.

## 9. Player commands and UI
UI surfaces function strictly as projection layers. Panels query current read-models from host sessions and format numbers/labels using localized tokens. Player input translates into typed command DTOs passed to host sessions.
