# l10n micro-location drift repair (T02) — micro_frozen_bus and siblings

## Goal

Repair the runtime localization drift that makes the Godot UI display a stale
`discovery.<id>.description` instead of the authoritative JSON text. The known
FAIL was `--expedition-panel-uitest` check `longest description text preserved
without truncation` for `micro_frozen_bus`.

## Root cause (evidence)

- `Assets/StreamingAssets/Data/micro_locations.json` is the authored authority
  (AGENTS rule 3). Round-54/55 prose trims folded a final clause into seven
  descriptions and mirrored it into
  `Assets/Ashfall.Core/Localization/LocalizationService.cs`, but **not** into
  `assets/l10n/strings.csv`.
- At runtime `AshfallLocalization.Initialize()` loads `strings.csv` through
  `LocalizationService.LoadFromCsv`, and `RegisterString` **overwrites** the
  Core defaults. So the CSV — not the Core literal — is what the panel renders.
- `src/UI/ExpeditionPanel.cs:1034` resolves `discovery.<id>.description` through
  `AshfallLocalization.Tr`, returning the truncated CSV text; the uitest asserts
  the body label contains the full JSON description and fails.
- Reproduced before change: `--expedition-panel-uitest` → 58 PASS / 1 FAIL,
  `[FAIL] longest description text preserved without truncation`.

Audit of all 28 micro-locations found the same class of drift in seven EN rows
(roadside_memorial, crashed_truck, frozen_bus, improvised_grave,
drainage_pipe, rail_siding, ruined_greenhouse) and three DE rows whose Core
translation already contained the folded clause (roadside_memorial,
crashed_truck, frozen_bus).

## Non-goals

## Changes (files)

1. `assets/l10n/strings.csv` — synced the seven drifted EN descriptions to the
   exact JSON text and the seven DE descriptions to the folded-clause form
   (Core literal where one exists; matching clause translation otherwise).
2. `Ashfall.Core.Tests/Localization/StringsCsvLocaleGateTests.cs` — added two
   focused gates:
   - `Catalog_MicroLocationEnglishMatchesAuthoritativeJson`: every
     `discovery.<id>.title|description|choice.<choiceId>` EN row in `strings.csv`
     equals the authoritative `micro_locations.json` text. This is the runtime
     path the existing `MicroLocationLocalizationTests` (Core defaults only)
     does not cover.
   - `Catalog_MicroLocationMatchesCoreDefaults_EnglishAndGerman`: instantiates
     a Core-default `LocalizationService` and a CSV-loaded one, then asserts
     the CSV override agrees with Core for all 135 micro-location keys (EN
     always; DE wherever Core registers a distinct German translation). This
     closes the Task-6 "two copies can drift apart" finding: the CSV may add
     German coverage but can no longer silently override Core's German.
3. `assets/l10n/strings.{en,de}.translation` — regenerated by the Godot
   csv_translation importer (`run-godot-bounded.sh --path . --import`) so the
   derived resources match the source CSV. `strings.source.translation` is inert
   and unchanged.
4. `docs/INDEX.md` — regenerated with the owning generator
   (`scripts/ci/generate-docs-index.py`) so the shared index reflects the
   updated `INTEGRATION_PLANS.md` / `WORKTREE_OWNERSHIP.md` entries and the
   corrected discovery docs; `--check` now passes.
5. `docs/discovery/MICRO_LOCATION_LOCALIZATION.md` — §3.1/§3.2/§3.4 documented
   the same three stale German descriptions; synced them to the corrected
   translations.
6. `docs/discovery/MICRO_LOCATION_TEST_MATRIX.md` and
