# Plan 08 — Visual Art Completion: Locations, Portraits & Icons

> **Theme:** Close the art backlog measured by the project's own coverage gate. Location art is
> the single biggest visual hole in the game (18.5% coverage); portraits are half-done.
>
> **Key evidence:** `docs/visual/ASSET_COVERAGE_REPORT_2026-08-26.md` (generated by
> `--asset-coverage-report`): items 287/315 (91%), factions 36/43, portraits 108/205 (52.7%),
> **locations 50/271 (18.5%)**. 28 missing item icons are individually listed.
> Pipeline: `ashfall-design` / `ashfall-foundry` skills, LFS for images, `.import` presets.

---

## Task 8A — Wasteland location art sprint (top 40 of 221)

**Goal:** Produce illustrations for the 40 most-visited wasteland locations, replacing
danger-colored node markers and fallback art where players actually look.

**Files:** `assets/art/` (new `.jpg`/`.png` + `.import`), `docs/visual/ASSET_COVERAGE_REPORT`
regeneration, possibly `assets.json` registry entries per the asset gate.

**Substeps:**
1. Rank the 221 missing `location` ids by player exposure: expedition destinations, questline hubs, faction seats, war-arc strike sites (cross-ref `questline_master.json` + `locations.json` tiers).
2. Lock the top-40 list; record the ranking rationale in the plan commit message.
3. Read `docs/visual/ART_FAMILY_REFERENCE_GUIDE.md` — match established palettes/composition families so new art doesn't drift.
4. Generate each illustration via the `ashfall-design`/`ashfall-foundry` pipeline (local Linux tools as production authority; AI generation only as reference/seed per skill rules).
5. Batch 1: 10 faction-seat & quest-hub locations (highest exposure).
6. Batch 2: 10 expedition mid-tier nodes on the main routes.
7. Batch 3: 10 faction-war strike/aftermath sites (pairs with Plan 06C's override text).
8. Batch 4: 10 deep-coast/dive/crossing sites.
9. For every file: Godot `.import` preset (filter/mipmaps/compression per existing art), Git LFS tracking verified (`git lfs ls-files`).
10. Register in the asset registry; run `--asset-registry-selftest` (48/48) + `--asset-coverage-report`.
11. Run `ashfall-lfs-gate` and `ashfall-shader-material-lint`.
12. Regenerate the coverage report; confirm locations ≥ 33% and no regressions elsewhere.

**Next steps:** second sprint for the next 60; location art feeds map panel polish and the future decor/trophy feature.

## Task 8B — Portrait completion pass (97 missing)

**Goal:** Close the portrait gap so named characters and cohort recruits stop falling back to
`placeholder_survivor.png`.

**Files:** `assets/sprites/Characters/` (or the portrait family dir per the art guide),
coverage report.

**Substeps:**
1. Split the 97 missing ids: named campaign survivors (highest value) vs procedural cohort/recruit pool (template-able).
2. Read `docs/visual/ASSET_GALLERY.md` + portrait family conventions (framing, background treatment, desaturation grade).
3. Produce named-survivor portraits first (~30): each with a distinct, grounded face consistent with their `characters.json`/`survivors.json` profile (age, trade, affliction hints — no glamor).
4. Build 6–8 reusable cohort archetype templates (medic, mechanic, farmer, soldier, elder, youth) covering the procedural pool by mapping rather than 1:1 art.
5. Wire archetype fallback mapping (data or resolver) so every cohort id resolves to a non-placeholder portrait.
6. `.import` presets + LFS for all files.
7. Run coverage report → portraits ≥ 90% (archetype mapping counts only if the registry resolver counts it — verify how resolution works first).
8. Run `ashfall-lfs-gate` + asset-registry selftest.
9. Snapshot check: `SurvivorsPanel`-adjacent golden images may shift — run the snapshot-diff workflow and approve deliberately.
10. Update the coverage doc with the new totals.

**Next steps:** portrait states (sick/injured variants) keyed to `SickListSystem` bands — high-value polish after this lands.

## Task 8C — Item-icon sweep + faction emblem completion

**Goal:** Knock out the two smallest, cheapest gaps: the 28 named missing item icons and the
7 missing faction emblems — closing items/factions to ~100%.

**Files:** `assets/art/` (item icons), `assets/ui/FactionEmblems/` + `assets/sprites/Factions/`
(emblems), `docs/visual/FACTION_EMBLEMS_ENCYCLOPEDIA.md` (read first).

**Substeps:**
1. Take the 28 item ids verbatim from the coverage report (`spring_mechanism`, `phonograph_needle`, `projector_bulb`, `film_reel`, `soldering_kit`, `item_ammonium_nitrate_sack`, … — the report lists all 28).
2. Check each id still exists in `items.json` (drop stale ids, note removals).
3. Read the item-icon family conventions (188-item contact sheet `assets/art/188_items.jpg` shows the house style).
4. Produce the 28 icons in 2 batches; keep background/lighting identical to the family.
5. For the 7 missing factions: read the emblems encyclopedia; determine whether each is a real faction needing art (`iron_garrison`, `cult_of_ash_sign`, …) or a legacy alias that should be remapped/removed instead of drawn.
6. Produce emblems for the real ones; remap aliases in the registry (don't draw art for dead ids).
7. `.import` + LFS + registry for all.
8. Run `--asset-coverage-report` → items ~100%, factions ~100%.
9. Run `ashfall-lfs-gate`, asset-registry selftest, snapshot diff on inventory/faction panels.
10. Full `dotnet build` + data-integrity selftest green (ids untouched, but prove it).

**Next steps:** with coverage at ~100% for items/factions, flip `--asset-coverage-report` from
report-only to a *gating* threshold for items/factions so the backlog can't regrow.
