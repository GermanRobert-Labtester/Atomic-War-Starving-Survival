## How to use this folder

1. Read `00-master-roadmap.md` first — it ranks 20 next steps (P0 → P3) with evidence and
   Definition of Done for each.
2. Each top-priority item also has a standalone execution plan (`01-*.md` … `05-*.md`)
   containing the 2-line goal, exact file list, implementation steps, and verification commands
   required by the ASHFALL task workflow.
3. Execute **one plan per task**. Run the full verification checklist before claiming done:

```bash
dotnet build Ashfall.Core.Tests/Ashfall.Core.Tests.csproj
dotnet test  Ashfall.Core.Tests/Ashfall.Core.Tests.csproj
dotnet build Ashfall.csproj
godot --headless --path . -- --data-integrity-selftest
godot --headless --path . -- --bridge-selftest
```

### Recurring structural pattern across all 30 plans
Almost every task is **content/wiring on a live system**, not a new system. The repo's real
gaps are: (1) thin catalogs on rich systems, (2) authored-but-unwired data (06C), and
(3) a few hardcoded-in-code catalogs that violate the JSON-authority invariant (Plan 34 research,
Plan 33 skills). New *systems* are rare and always flagged (12C decor, 15C NG+, #17 cloud seeding).

### The late-game narrative spine (25 completes it)
`25A peace → 25C escalation → 06C war → 25B muster → 15A epilogue` — the connective content
that turns separate expansions into one arc.

**Suggested sequencing:** Plans 01–03 (verification/hygiene) → 06C (biggest ready-made
activation) → 04/05/07A (cheap wins) → then 08–15 by interest, respecting the arrows above.
Any task touching ≥2 coupled variables or a new system requires **cross-tool QA**
(implementer ≠ reviewer) per `AGENTS.md`.
